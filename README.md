# Open Medical · 医疗 AI 工作台

[中文](./README.md) | [English](./README_EN.md) · License: [MIT](./LICENSE)

本地优先的开源桌面 Agent 工作台（Windows / macOS）：无需云端账户、业务数据本机保存（使用外部模型时按授权发送所选内容）、模型自行配置（DeepSeek / OpenAI / Anthropic / 任意 OpenAI 兼容接口 / 本地 Ollama），密钥本地加密存储。桌面打包见 `npm run package:mac` / `npm run package:win`，构建流程由 GitHub Actions（`.github/workflows/build-desktop.yml`）双平台验证。

## 医生工作台闭环（2026-09-22）

项目定位：**完整通用 Agent / Harness 底座上的医生工作台**。患者建档、临床资料、材料整理、知识库、风险复核和随访围绕同一患者衔接，通用 Agent 入口与能力继续保留。

当前已串联今日待办、患者建档与名单导入、诊前速览、带来源的档案提案复核、检查转诊跟进、随访结果与追加更正，以及知识库来源和版本复核。首次使用与完整操作链路见 [医生使用指南](docs/DOCTOR_WORKBENCH_GUIDE.md)，研究与执行安排见 [八小时优化计划](docs/DOCTOR_WORKBENCH_8H_PLAN.md)，验证进度见 [本轮验收记录](docs/DOCTOR_WORKBENCH_ACCEPTANCE_20260922.md)。以下版本段落为历史交付记录；“顶尖 Harness”仍需持续通过真实任务与稳定性验收。

## 直接运行

需要 Node.js ≥ 22.13 及 npm。SQLite 在部分 Node 版本会打印 experimental 提示。

```bash
npm install
npm run build
npm start
```

打开 <http://127.0.0.1:8787>。一个 Node 进程同时提供页面、API、SSE 和 WebSocket，只绑定本机。不需要配置模型即可使用本地整理、患者建档、随访提醒和消息归档。

## 任务驱动的工作台

首页选择病例整理、检验摘录、用药资料、随访或循证准备场景。关联患者时沿用该患者的病例工作区；独立任务单独建立工作区。准备任务后添加材料，再执行并核对成果。待复核入口汇集草稿，复核后可继续进入同一患者的随访计划。

产品形态、对象关系、路由与后续设计见 [产品设计说明](docs/PRODUCT_DESIGN.md)。

## 本地工作区

左侧「本地工作区」连接文件夹，浏览与检索文本，提出文件修改，查看前后内容并批准。任务支持流式模型、停止、只读子任务、历史分支和单次/间隔计划。授权变化后，旧上下文和计划不能沿用更大的权限。模型和原件均不会因“创建工作区”而自动上传。目录外访问、密钥文件和符号链接受限。

`npm run workspace --` 查看无需医疗服务器的独立 CLI。数据保存在本机，默认 CLI 数据库和医疗工作台数据空间分开。功能、限制、接口和本地模型配置见 [GENERIC_RUNTIME.md](docs/GENERIC_RUNTIME.md)。

## 患者管理闭环

1. **建档**：新建患者（姓名、性别、出生年、电话、分组、标签），自动建立该患者的病例工作区会话。
2. **导入病例**：在工作区导入 TXT、Markdown、CSV、JSON 或有文字层的 PDF（纯文本 ≤2MB；PDF ≤20MB / 300 页，浏览器本机解析，只保存抽取文本，不存原件；材料自动建立本地检索索引，模型按需取相关片段）。
3. **自动整理病例**：一键发起本地整理，时间线 / 检验摘录 / 用药核对三个子代理并行产出草稿，全部附行号、PDF 页码和 SHA-256。
4. **评估治疗方案**：模型辅助下生成固定结构的参考意见草稿（现状摘要、需关注点、信息缺口、建议核对的问题），产物默认待复核。现有内置用药与检验规则覆盖有限，不提供完整药物安全保证。
5. **随访计划**：按天数间隔到期执行——生成待办提醒；授权后可自动把该患者未处理消息原文发送给模型做记录摘要，消息随后标记已处理。失败即暂停并留痕，不自动重放。
6. **消息归档**：手动粘贴、由本机微信 CLI 推送，或在 macOS 上用内置微信桥接同步当前聊天窗口（去重、自动按电话/姓名归属、未识别的进入待认领收件箱），AI 总结后进入病例工作区待复核。系统永远不会自动向患者发送消息。
7. **提醒与反馈**：患者总览聚合待办提醒、到期随访、未处理消息和待认领消息。到期后登记实际联系结果、核对条目和后续计划，记录持久保留于患者随访页。

数据（患者、消息、随访、提醒、会话）全部保存在本机 SQLite；删除患者档案会级联删除其工作区和记录。macOS 微信桥接（界面自动化，默认关闭需授权，发送逐条确认）详见 [docs/PATIENTS.md](docs/PATIENTS.md)。

## 任务工作区

从任务记录或患者档案进入三栏工作区：会话式整理（时间线、检验摘录、PICO 检索计划、用药核对）、产物人工复核与版本历史、Markdown/JSON 导出、计划任务与隔离计算。患者病例工作区就是这个会话体系的一部分，在列表中带「患者」标记，只能从患者档案侧删除。

## 配置模型

复制 `.env.example` 为 `.env`，通过 `AI_PROVIDER` 选择 `deepseek`、`openai`、`openai-compatible`、`openrouter` 或 `anthropic`（Claude），填写密钥后重启。服务在 `/api/bootstrap` 报告当前 provider 和模型。

每轮模型外发必须逐次勾选同意；**外发内容是原文**（患者材料、消息或其上下文），发送前请自行确认范围。定时计划与随访的自动总结需要单独的重复外发授权。`reasoning_content` 与工具消息只留在本机运行记录，不出现在普通导出中。数据库未加密。

```bash
npm run verify:model   # 有密钥时验证真实 SSE、工具调用与续轮
```

## 数据与恢复

数据位于 `server/data/medical.sqlite`（`MEDICAL_DATABASE` 可指定路径）。SQLite 事务防并发覆盖，文件锁阻止双运行时；重启后未完成执行标记为「已中断」。当前 schema 8 在既有数据库上增量升级，新增检查与转诊跟进记录；旧库启动时按版本迁移。

```bash
npm run backup         # 一致性快照，兼容 schema 2–8
```

恢复：停服后把 `MEDICAL_DATABASE` 指向备份副本再启动。已被执行引用的材料不能单独删除；删除患者会同时删除其工作区、消息、随访与提醒，但不影响已导出文件和备份。

## 边界声明

本项目不包含微信协议实现；消息接入只提供本机 HTTP 契约，第三方 CLI 的账号与合规风险在项目之外。系统不做临床分诊、不判断急症、不给出剂量建议，所有 AI 产物均为待医生复核的草稿。多人权限、全库加密、防篡改审计、药物安全知识库、HIS/EMR/FHIR 对接和机构部署验收尚未实现。0.8 新增的 OAuth 凭据加密与通用 OCR 助手不等于患者数据加密或医疗 OCR 流程验收。
