# 医生工作台定位与链路补齐（2026-09-22）

> 这是八小时自主优化之前的阶段记录。后续已增加分页、追加更正、检查转诊和诊前速览；当前行为请以 [医生使用指南](DOCTOR_WORKBENCH_GUIDE.md) 与 [本轮验收](DOCTOR_WORKBENCH_ACCEPTANCE_20260922.md) 为准。下文保留当时实现及边界供追溯。

## 定位

Open Medical 是通用 Agent / Harness 底座上的医生工作台。通用文件操作、终端、浏览器、技能、工具编排、上下文管理、任务恢复及成果验证是底座能力；患者、临床材料、知识来源、风险复核和随访是领域能力。医疗页面不能成为限制通用能力的另一套弱化运行时。

本轮沿用现有 AgentRuntime、SessionBridge 和医疗领域适配，不改变工具授权、模型权限或任务恢复机制。“顶尖 Harness”是持续验收目标，不是已经取得的认证。现有真实模型与长任务证据见 [底座验收](agent-foundation-acceptance-2026-09-21.md) 和 [Beta 验收](beta-readiness-2026-09-21.md)，历史成功不能替代当前版本长时验收。

| --- | --- | --- |
| 日常入口 | 场景、会话、患者列表与工具箱 | 首页提前呈现待办概况；建档、知识库、通用 Agent 直达；到期随访直达随访管理 |

## 随访数据语义

- `follow_ups.status=completed` 只代表单次计划执行完成、提醒已生成，不表示医生已联系患者。
- `reminders.outcome` 保存医生登记的联系结果：`completed`、`unreachable`、`declined`；包含 `note`、`checkedItems`、`recordedAt`、`nextFollowUpId`、`nextDueAt`。
- `POST /api/reminders/:id/complete` 登记结果。已有结果返回 409，避免覆盖既有记录或重复创建下次提醒；历史已读但无结果的提醒可以补登记。
- `GET /api/reminders?status=pending|done&patientId=...` 支持患者范围；已登记内容随患者删除与备份遵循原有 reminders 生命周期。
- 可选下一次提醒与本次结果、审计同一事务；失败整体回滚。下一次提醒默认不授权模型外发；原有周期计划保留。
- 系统只向医生呈现本机提醒，不自动发送患者消息。当前服务需要运行才能触发计划；页面每 15 秒刷新提醒，重新打开也会读取持久记录。
- 默认读取前 100 条提醒；本轮未新增完整病历级分页、签署、随访记录更正工作流。

## 风险能力边界

本轮没有新增临床阈值或扩大内置药物规则。检验项需要精确匹配支持的名称、单位；不自动换算不兼容单位，不使用旧兼容结果替代最新不兼容结果。风险规则只覆盖已录入结构化字段，未触发不代表无风险；最新资料无法套用规则时，也不能把历史提示消失解释为临床安全。

首页展开风险后可重新检查全部患者资料和逾期随访；资料更新、新建档案及随访登记也会检查相关患者。规则没有经过临床有效性验收，机构阈值、采样背景、规则版本治理及完整药物库仍需建设。

## 仍需完成的产品级工作

1. **Harness 稳定性**：当前冻结版本的真实模型多任务、多供应商、长上下文、48 小时负载与故障恢复；Windows 实机与分发签名验收。已有入口不等于所有环境已通过。
2. **患者长期档案**：结构化就诊 / 问题清单的纵向管理，重复患者合并、误操作恢复、完整历史分页及随访记录更正 / 签署。目前删除仍沿用原有级联语义。
3. **医疗级知识治理**：来源与版本有效期、更新提醒、机构审核、适用人群、撤回资料引用提示；扫描 PDF / 医疗 OCR 的质量验收。
4. **机构部署**：多人身份与角色、患者访问权限、患者数据全库加密、防篡改审计、恢复演练及 HIS/EMR/FHIR 集成。现有本机单医生版本不等于机构上线条件。
5. **临床规则验证**：专业人员审核规则与阈值，带标注病例集评估误报 / 漏报；不能靠界面测试宣称临床可用。

## 验证

本轮增加服务端随访闭环与真实 Chromium 界面回归；沿用项目完整 Node 测试、真实 Electron/Chromium 场景、ESLint 和生产构建。所有新测试采用合成患者与隔离数据库。最终结果记录在本文件末尾；未执行的外部模型、跨平台或长时项目不会计作通过。

- ESLint 与生产构建通过；保留既有大型 chunk 提示。
- 完整回归：679 项，662 通过、0 失败、17 按环境条件跳过。包括通用 Agent、患者域、Chromium 与 Electron 场景。日志：`output/care-continuity/regression-final.log`。
- 最后整理知识库导入表单并补上“基于随访记录继续任务”后，重新构建，针对全部受影响链路运行 24 项回归，24/24 通过、无跳过。日志：`output/care-continuity/focused-final.log`。
- 浏览器实际验证：建档后的流程入口、临床保存冲突保留输入、随访登记与刷新后回读、结果带出处回到同一患者任务、知识文件上传 / 元信息 / 索引 / 原文 / 待发送循证任务。截图：`output/care-continuity/patient-followup.png`。

随访结果继续任务只预填输入框，并保留患者会话、记录 ID、登记时间与原文；仍需医生核对并发送，不自动调用模型。未开展新一轮跨供应商、Windows 实机或 48 小时长负载验证。
