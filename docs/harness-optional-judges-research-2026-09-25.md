# Harness 可选判断器：Jev / mu 调研与接入建议

日期：2026-09-25。状态：下文为完整架构建议；已实现其中的默认关闭、可选后台观察入口，未调用真实 Jev API、未做本项目效果评测。

## 首版已实现范围

设置 → 决策辅助 · Jev：默认关闭；可配置独立密钥、模型、超时和任务文本发送许可，保存后对后续任务判断生效。连接测试发送固定合成文本，不保存、不启用。通用和医疗服务器均提供经过现有认证的 `/api/jev-settings` 与 `/api/jev-settings/test`。

启用后，在 WorkspaceService 主执行路径的新任务开始时进行一次 `input.preflight` 任务类型观察。结果记录为 `decision.observed` 事件，设置页重新打开时可看到本进程最近结果；不会注入提示词，不会调整工具、模型、权限或完成判定。子代理和旧任务恢复不额外调用。当前只支持 shadow，不包含下文建议的 active、技能推荐或自动模型路由。

只发送当前任务文本；超过 4000 字符直接跳过，不附加历史、文件或附件。开启必须明确同意文本外发。默认超时 1500ms，失败不重试并沿用原流程，取消信号传播；关闭不会撤回已发出的请求。密钥用现有 CredentialVault 加密，不接受任意 endpoint 或重定向。

验证：`tests/jev-settings.test.mjs` 覆盖默认零请求、许可、独立密钥、固定测试输入、响应校验、超时/取消、加密持久化、真实工作区执行接线和双服务器 API。使用模拟上游，不代表真实服务连通性或分类质量已验证。

## 结论

可以让用户选择是否接入 Jev。建议保留现有 harness，在其上增加可插拔的决策辅助层，而不是引入另一套 agent 主循环。主执行模型、判断器和权限策略应独立配置。

第一期价值：技能推荐、模型档位建议、判断记录。工具裁剪、上下文淘汰先做 shadow 对照。自动批准外部操作、医疗结论判断、以模型意见代替交付验证不纳入第一期。

## 外部项目与可用性

### qybaihe/mu

[仓库与 README](https://github.com/qybaihe/mu)将判断拆成独立决策点，每点支持 off / shadow / active，可配置 Jev、本地 Laya、通用 LLM 或级联。覆盖技能发现、工具输出筛选、上下文、任务漂移和协作消息等。

最适合借鉴的是“逐点配置 + 判断记录 + 观察后启用”。mu 是建立在 pi 与 AionUi 上的完整应用，不能视为本项目直接安装即可使用的插件。README 标明核心 MIT、桌面 Apache-2.0；若复用代码，仍需逐文件核对第三方声明。其延迟、上下文收益是作者报告，不是本项目验证结果。本次读取了 README 与根 package.json，未完成其判断内核源码审计。

### Jev 接口本身

[官方简介](https://docs.typesafe.ai/introduction)定义 Choice、Score、Noul，用状态和明确问题得到结构化判断。[官方 quickstart](https://docs.typesafe.ai/introduction/quickstart)提供 `POST https://api.typesafe.ai/v1/systemone`，以 Bearer key 鉴权，请求包含 state、model、questions，响应含 answers 与 usage。

因此 Node 服务可通过独立 HTTP adapter 接入，无需更换主模型。它不是现有聊天 provider 的同协议替代品。生产评测应记录实际返回的模型版本；不要只记录会漂移的 latest 名称。

### TypeSafeAI/jev-harness

[仓库](https://github.com/TypeSafeAI/jev-harness)提供判断、收据与动态工具上下文的参考接口；仓库自述为独立社区项目，不能因为组织名称就认定是官方生产保证。可借鉴其输入验证、证据绑定和宿主保留执行权的设计。

[2026-09-23 实验](https://github.com/TypeSafeAI/jev-harness/blob/main/docs/routing-evaluation/2026-09-23.md)尤其重要：57 对重复合成试验的输入 token 总量下降 61%，但在实际选择工具的 30 对中，正确工具表现由 27/30 降为 15/30。部分写入任务漏掉了前置读取工具。作者明确建议多步任务保持 shadow。该结果不证明成本下降、端到端加速或任务完成率提升。

### JoacoMarc/jev-harness-router

[仓库](https://github.com/JoacoMarc/jev-harness-router)提供目录驱动的模型、effort、工具与技能路由，以及 deadline 和 fallback。适合参考“限定候选集合 + 有期限的请求 + 来源标记”。其默认时间限额和准确率来自作者环境，不宜直接套用到中文医疗工作流。是否直接依赖该包，需另外审核实现、许可证和依赖；第一期自建薄 adapter 更容易对齐本项目权限与事件模型。

## 用户配置建议

设置入口使用“决策辅助”，解释为帮助选择技能、模型和工具的辅助服务。

- 默认：关闭，沿用当前 harness，不发判断请求。
- 服务：Jev；后续支持已有模型配置、本地判断模型。未实现的服务不显示为可用。
- 接入信息：独立 key、连接测试、实际模型版本、数据发送范围。
- 每项能力：关闭 / 仅观察 / 启用；“仅观察”仍会发送获准的数据并可能计费，文案必须说明。
- 优先支持：技能推荐；模型档位先展示建议，用户开启自动路由后才切换。
- 高级设置：超时、单轮调用上限、用量预算、失败回退说明。
- 记录页：判断点、模式、来源、耗时、实际模型、是否采纳、回退原因；用量缺失显示未知。

应用默认值可由工作区覆盖；每次运行保存有效配置快照与策略版本。修改设置影响新运行，避免恢复旧检查点时无意改变语义。配置快照不得包含明文 key。

“仅本地处理”应是独立的数据策略；若选择 hosted Jev 且输入不允许外发，直接跳过判断，不自动转发到其他云模型。患者标识、原始病历、附件默认不交给新增的判断服务；优先只提供工具目录、任务类型等最少信息。脱敏不能默认等同于没有敏感信息。

## 接口与约束建议

新增 `decision-service.mjs` 负责模式、deadline、预算、输入策略、校验与记录；`judges/jev.mjs` 仅处理请求和响应。接口概念：

```text
decide(point, allowedState, candidates, signal)
  -> status, suggestion, source, model, usage, latencyMs, fallbackReason
```

1. off：零网络调用。shadow：只记录建议，不改变模型、工具、上下文和权限；有独立时间上限，并传播取消信号。
2. active：校验返回类型、候选 ID、数值范围和实际模型；缺失、越界、低把握或超时回退到当前策略。阈值需要按本项目样本校准。
3. 回退只恢复本来允许的行为，不能把审批失败、权限拒绝变为放行。未来若引入新的硬性 gate，必须为它单独设计故障语义。
4. 工具建议只能从权限和就绪过滤后的集合选择；不会注册工具或扩大权限。采用能力组合，保留读取、发现、纠错、归档回读、验证与审批所需前置工具。
5. 用户明确选择的模型、技能和限制优先；新输入到达后废弃旧任务版本的建议。跨 profile 切换必须重新计算上下文预算、模型能力和工具协议。
6. 判断不能证明文件写入、测试通过或任务完成；继续使用 `onDelivery`、`onApprovalReady` 及服务层执行事实。
7. 日志保存结构化结论与输入指纹，默认不落原始病历或完整 state；缓存键含工作区、任务版本、候选集合、策略和模型版本，避免跨患者串用。

## 实施顺序与验收

**第一步：配置、adapter、仅观察、判断记录。** 用合成中文任务测试连接；不上传真实工作区数据。覆盖取消、超时、429/5xx、畸形响应、候选越界、key 脱敏、关闭时零调用，以及 shadow 不改变执行决策。

**第二步：技能推荐及可选模型路由。** 与原流程成对比较，记录任务交付质量、必要技能召回、误降档、端到端延迟、缓存命中、主模型与判断器总用量。已有用户指定不得被覆盖。用普通 LLM 作判断器时重新评测，不能假定与 Jev 等价。

**第三步：工具组合筛选。** 从当前 evals 和集成测试抽取读取后写入、报告生成、附件处理、团队协作及审批恢复任务；保留失败与回退样本。必须先证明必要前置工具未被过滤，不能只凭 token 下降启用。

**后续：上下文片段判断、本地模型与级联。** 独立验证中文、精确数字/剂量/单位、否定、时间顺序和用户修正的保真。与当前压缩改动分开验收；原文可回读不等于删掉事实没有后果。

交付判断：目前证据足以支持“实现可选、默认关闭的实验接入”，不足以支持“默认开启”或宣称提升医疗任务准确率。实际可用性仍需本地网络下的 API 测试和本项目成对评测。
