# 医生工作台：从第一次建档到持续随访

当前实现说明，更新于 2026-09-22。目标用户暂按单医生门诊与慢病连续管理；需求来自公开工作流研究和现有代码问题，尚未完成真实医生访谈。

## 产品定位

Open Medical 在完整通用 Agent / Harness 之上组织医生日常工作：围绕同一位患者保留资料、事实、来源和处理记录，让“接诊 → 整理 → 复核 → 跟进”可以连续进行。文件、浏览器、终端、技能、MCP、协作、上下文管理、任务恢复仍使用原有通用底座。

医生不必先理解工具参数。首页先显示今天需要处理的事；可从患者或一个具体任务开始。模型配置和运行细节保留在设置与任务内。

## 第一次使用

1. 启动服务并打开工作台。无需模型即可建档、登记临床资料、随访和检查转诊记录。
2. 点 **患者建档**。建议填写稳定的患者编号；姓名相同时先打开已有档案核对，确为另一人时再确认新建。
3. 已有 Excel 名单时点 **导入已有患者**，粘贴表格或选择 CSV。先预览，再勾选要导入的行。相同编号与姓名会跳过；编号冲突必须纠正；同名患者需要逐项确认。每批最多 200 行，只导入身份和分组字段。
4. 从患者档案核对过敏史和用药状态。空白过敏史显示“尚未核对”；停用药保留在档案中。
5. 需要模型整理时，在模型设置中完成配置，再为本次任务选择患者与材料，按界面确认外发范围。首次准备任务不会自动发送材料。

批量导入不覆盖既有档案，也不自动合并患者。患者临床资料应通过材料整理或临床资料页补充。

## 一个完整的接诊流程

| 医生要做什么 | 入口与操作 | 保存在哪里 / 下一步 |
| --- | --- | --- |
| 看今天有谁需要处理 | 首页“今天要处理的事”，按随访、检查转诊、患者消息、风险、待复核筛选 | 点具体事项进入对应患者和来源；完成后队列更新 |
| 接诊前快速回顾 | 患者档案中的诊前速览 | 诊断、在用/停用药、过敏核对状态、近期检验、联系记录、未完成事项及来源 |
| 整理新报告或病史 | 患者任务中添加材料，再发起整理 | 保留原文和来源；临床更新生成提案，尚未写入档案 |
| 核对模型提取结果 | 待复核中“核对变更” | 对照当前记录和采纳后内容，确认后写入；旧版本提案不能覆盖后来的修改 |
| 做诊后文书或准备问题 | 诊前/诊后任务入口 | 带患者摘要的待发送草稿；医生选择材料与授权后执行，再复核输出 |
| 等待检查或转诊结果 | 患者“检查与转诊”新建事项，填到期时间 | 到期进入首页；收到结果后进入医生核对，再登记告知和后续安排 |
| 联系患者并安排下次 | 随访提醒点结果登记，或患者随访页主动登记联系 | 联系结果、实际时间、核对条目、记录与可选下次提醒一并保存 |
| 补充一条既有联系记录 | 历史记录中追加更正 | 保留原始记录和追加内容，不覆盖过去的记录 |

诊前速览是有限长度的摘要，计数反映完整记录数量。完整资料仍在患者档案与材料中。检验趋势只比较同项目、同单位、不同日期的记录；同日冲突会显示待核对，不悄悄选一个数值。

## 检查与转诊：四步闭环

**待收结果 → 待医生核对 → 待告知登记 → 已结束**。

收到结果时填写结果来源；医生核对时保留处理记录；结束时登记已告知或无需告知的理由。可以同时安排下次随访。调整时间、取消和重开均保留历史。单纯生成提醒或收到报告不会被标记为已完成整个流程。

这里管理的是本机跟进记录。医院检验系统和转诊系统尚未接入，结果来源需要医生自行登记。

## 随访：计划和联系是两件事

- 到期计划生成医生待办；“计划已执行”表示提醒已产生。
- 联系结果单独登记为已完成联系、未联系上或患者拒绝；实际联系时间和后续安排保留。
- 下一次提醒默认不授权模型外发；原有周期计划不会因一次联系记录被自动取消。
- 历史记录支持分页和追加更正。重复提交不会重复创建下一次提醒。
- 服务运行时触发计划；关闭应用且后台服务未运行时，不会在关机状态发送提醒。重新打开后读取持久待办。

工作台不会因为登记随访而自动给患者发消息。

## 知识库：知道出处，也知道是否复核

导入指南、共识或资料后，先记录标题、来源链接、版本和建议复核日期。默认 **未复核**；医生检查原文后标为 **已复核**，不再使用的资料标为 **已停用**。修改来源信息会撤销原有复核状态。

搜索可按类型、集合、复核状态筛选；默认排除停用资料。命中结果可查看原文、行号和来源，并带入一个待发送任务。标记“已复核”仅记录医生做过来源核对，不代表内容已经获得临床有效性认证或永远保持最新。

患者材料与公共知识分开处理：患者材料只使用明确配置的本地嵌入；未配置时可用关键词检索。选择外部模型执行任务时，所选材料及任务上下文仍可能按授权发送给模型。

## 使用时容易混淆的地方

| 界面状态 | 实际含义 |
| --- | --- |
| 过敏史尚未核对 | 没有完成核对，不能当作“无过敏” |
| 药物已停用 | 保留历史记录，当前风险检查不当作在用药 |
| 已生成提案 | 尚未写入正式患者档案，需要医生确认 |
| 提案与当前档案版本冲突 | 档案已被修改，需要重新读取并生成提案 |
| 风险已确认 / 已处理 | 保留对当前证据的处理状态；新证据或复现可能重新提醒 |
| 患者已归档 | 在归档筛选中查看、恢复；不再进入日常待办，不能继续采纳写入提案 |
| 通用 Agent | 可独立处理研究、文件和项目任务；患者病例不会混入项目列表 |

顶栏切换患者会改变当前工作对象；任务中的 @患者引用不会自动切换。患者会话里的临床、随访和病例提案须对应当前患者。

## 目前仍缺什么

这些是后续真实试点需要验证或实现的范围，不能用本轮测试代替：

- **真实医生试用与专科模板**：需要按首批专科观察接诊，测量完成任务时间、重复填写次数、错误率和复核负担。
- **机构系统联通**：HIS/EMR、检查报告、转诊、预约和收费接口尚未构成机构级闭环。
- **资料采集**：现有文本与有文字层 PDF 路径可用；语音门诊记录、影像诊断与复杂扫描件 OCR 尚未作为完整临床采集链路验收。
- **早期会话迁移**：新建患者和任务使用统一工作区；早期 `sessions` 表会话仍保留兼容运行路径。当前患者读取工具与本轮完整 Harness 链路的验收以统一工作区会话为准，旧会话迁移需单独验证，不在本轮批量重写用户历史数据库。
- **多人机构使用**：当前按本地单医生设计，角色权限、机构审计、签署、更正与长期归档策略需要单独设计和验收。
- **临床有效性**：风险规则覆盖有限，模型输出由医生复核；没有完成前瞻性临床效果验证。
- **分发与运维**：当前改动未覆盖已安装应用；干净系统、Windows 实机、签名发布和机构部署需独立验收。
