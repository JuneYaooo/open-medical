# Open Medical 项目功能梳理

> 更新日期：2026-10-10 · 基于版本 v0.9.80（main 分支）
> 本文档面向"这个项目有哪些功能"的全景速览；实现细节与验收记录见 `docs/` 下各专题文档。

---

## 一、项目定位

Open Medical 是一个**本地优先的开源医疗 AI 桌面工作台**（Windows / macOS），定位为"完整通用 Agent 底座之上的单医生工作台"：

- **本地优先**：业务数据全部保存在本机 SQLite，不需要云端账户；数据库文件 0600 权限、单进程锁。
- **模型自配**：支持 DeepSeek / OpenAI / Anthropic / 任意 OpenAI 兼容接口 / 本地 Ollama，密钥本地加密存储。
- **外发可控**：每轮模型外发必须逐次勾选同意；向患者发消息必须逐条人工确认。
- **AI 不直写**：所有 AI 产物默认是草稿，进入「待复核」，由医生逐项确认后才写入档案或发出。
- **安全边界**：临床有效性未验证，所有输出仅作参考，不替代医生判断；内置用药/检验规则覆盖有限。

架构一句话概括：**通用 Agent/Harness 内核（`server/core`）+ 医疗领域适配层（`server/medical`、`server/care`）+ Electron 桌面壳 + React 前端**。通用平台可独立运行（`npm run platform`），医疗只是其上的领域适配器。

## 三、医生工作台闭环

围绕"选对象 → 准备材料 → 整理生成 → 核对成果 → 继续随访"组织医生日常工作。

- **首页任务入口**（`workbench-home.jsx`）：自然语言描述任务，或选场景模板——病历时间线、检验摘录、用药核对、随访计划、循证准备；关联患者沿用其病例工作区，独立任务单独建工作区。
- **今日待办**（`doctor-agenda.jsx`）：聚合风险提示、复诊、随访到期、检查检验、患者消息、试验入组、自定义规则等工作项。
- **诊前速览**（`patient-brief.jsx`）：确定性本地只读摘要——诊断问题列表（确诊/疑似/发现/复核四组，同名诊断自动归并来源）、在用与停用用药、过敏核对状态、近期检验、联系记录。
- **材料整理**：上传材料后三个专用子代理并行产出草稿——时间线 / 检验摘录 / 用药核对，全部附行号、PDF 页码和 SHA-256 来源。
- **提案复核**（`pending-tray.jsx` / `patient-proposal.jsx`）：AI 提取的结构化信息不直接写入档案，医生逐项采纳；全局「待复核」托盘汇集发消息、随访计划、微信绑定、群发、批量初筛等一切需人工确认的事项。
- **检查转诊跟进**：四步闭环——待收结果 → 待核对 → 待告知 → 已结束。
- **诊后文书**：出院小结、交班记录、个案报告等草稿（见内置技能）。
- **材料识别质量闭环**（0.9.70+）：每份 OCR 转写先评分，乱码/低质量页自动升级视觉模型复核；来源页支持图文对照视图、手动修正文字、一键刷新病历记录。
- **后台建档**（`intake-background.jsx`）：上传与解析在服务端后台任务执行，切换页面不中断。

## 四、患者管理

- **建档**：新建患者（姓名、性别、出生年、电话、分组、标签），自动建立该患者的病例工作区会话；身份信息编辑防同名误合并。
- **名单批量导入**（`patient-import.jsx`）：Excel/CSV 批量导入，预览、勾选、冲突校验，每批 200 行。
- **结构化临床资料页**（`patient-clinical.jsx`）：诊断（ICD-10 辅助）、用药、过敏、检验、就诊史；本地编辑保存，可导出去标识 JSON。
- **患者仪表盘**（`patient-dashboard.jsx`）：诊断分组、检验趋势、时间线，每个结论可溯源到材料原文。
- **分组标签**：患者分组与自定义标签体系；**自动分组建议**（0.9.80）：按结构化诊断（ICD-10 编码/名称，20 条常见病规则）确定性派生疾病分组，无诊断命中时按常用药给「待核对」分组，扫描结果进待确认托盘，确认时逐患者乐观更新、冲突跳过并报告；分组 chips 即队列视图。
- **资料库视图**（0.9.79）：患者档案新增「资料库」tab——按确认后的类型（检验/影像/门诊/住院/用药）× 资料日期归类成报告文件夹，分类来自文件名与识别文本的确定性关键词推测（一键采纳），检验报告组头直接展示最新关键检验；图文对照与 OCR 质量徽章沿用。
- **复诊预约**（`appointments.jsx`）：登记复诊时间，前一天与当天自动进入今日待办。
- **风险提示**（`risk-rules.mjs`）：数据驱动的风险规则，仅提示并附证据，不做自动决策。
- **医生档案**（`doctor-profile.jsx`）：医生偏好记忆——显式编辑 + 从使用信号中产生候选，供 AI 起草时个性化。

## 五、随访与患者消息渠道

### 随访核心
- **随访计划**（`followups.jsx`）：按天数间隔设置时间/频率/清单，到期生成待办提醒；授权后可把未处理消息发给模型做记录摘要。
- **结构化随访问卷**（0.9.77）：随访计划可附多题型问卷（单选/多选/数值/简答，选项带分值、数值带越界预警、总分预警线）；到期生成问卷，经微信已验证发送/企微机器人/手动复制下发；患者按题号回复由**确定性解析器**自动回收计分（红旗优先、解析不出不消费消息），越界或总分过线进今日待办风险泳道；支持电话代填与模型解析草稿（医生确认后才生效）。
- **按患者检验监测**（0.9.76）：在检验趋势上为单患者设阈值（高于/低于）或复查间隔，越界/到期进入今日待办风险泳道，带完整证据，走既有的确认/解决闭环；内置通用风险规则不受影响。
- **随访记录**（`followup-records.jsx`）：提醒触发 ≠ 完成随访；实际联系结果（已联系/未联系上/患者拒绝）独立登记，可追加更正，记录持久保留。
- **失败即暂停**：随访自动总结失败不自动重放，留痕待人工处理。

### 消息渠道（微信 / 企业微信）
三条接入渠道（`server/chat-connectors/`）+ 一条回复链路：

- **微信桌面读取**：Windows 微信 4.x 通过本机 OCR 读取（身份核验 + 自动定位 + 增量去重）；macOS 走 wx-cli。
- **微信导出文件导入**（`wechat-import.jsx`）：手动导入聊天导出 TXT/ZIP，预览核对后生成随访草稿。
- **企业微信会话存档**：独立 Python 采集器（`integrations/wecom-archive/`），工作台不接触存档密钥。
- **企微智能机器人**（0.9.72+）：官方长连接（wss）实时接收群 @ 消息和单聊；红旗问题自动回固定安全话术，其余由患者简报+知识库起草进入医生审核队列。
- **微信智能回复**（0.9.74）：已绑定的单聊新消息按患者简报和知识库起草回复，进同一审核队列。
- **已验证发送**：向患者回复必须逐条人工确认；应用在发送前后核验微信窗口画面，任何核验不通过就不发送、不重试。
- **红旗安全规则**（`server/care/red-flags.mjs`）：确定性规则在模型调用前后双重执行，模型不能否决；外发内容屏蔽敏感信息。
- **自动回复分诊**（`care/triage.mjs`）：仅事务性类别可无人值守，临床判断类永远不可开启自动回复。
- **企微患者联系**（`wecom.mjs` / `wecom-directory.mjs` / `wecom-panel.jsx`）：官方客户联系 API 同步客户目录，医生确认"本人/家属"绑定；群发任务状态机（草稿→待发送→已发送≠已读→失败），断网保留"结果待核实"，禁止自动重发。
- **自动随访队列**（`chat-autofollow.jsx`）：到期 → AI 起草话术 → 医生确认发送 → 回收回复 → 整理归档，发送前/归档前双人工检查点。

## 六、临床辅助

- **临床速查**（`clinical-ref.jsx`，全部本地确定性输出，不依赖模型）：量表计算器、检验指标解读、ICD-10 诊断编码与 ICD-9-CM-3 手术编码查询、药物不良反应筛查。
- **临床辅助问答**（`clinical-assistance.jsx`）：按患者画像（诊断/用药）起草临床问题任务，模型辅助生成固定结构的参考意见草稿（现状摘要、需关注点、信息缺口、建议核对的问题）。
- **相似病例检索**（`similar-cases.jsx`）：本地病例库确定性相似度 + PubMed/Europe PMC 在线病例报告；多维结构化对比，摘要卡 + 全屏阅片器；只用于假设参考，不用于诊断。
- **病例库**（`cases.jsx`）：本地病例浏览检索、患者快照入库。
- **用药安全**（`med-safety.mjs`）：内置规则筛查，明确标注非穷尽，不提供完整药物安全保证。
- **患者教育**：把医生已有诊疗信息转成患者能懂的大白话，只转述不给新建议；**患教素材库**（0.9.78）：内置「患教素材」知识库，素材带来源/版本/复核状态（智能回复只引用「已核对」条目），支持一键按患者分组批量群发（走待确认提案，企微侧成员仍需手动点发送）。

## 七、知识库

- **多知识库管理**（`knowledge-libraries.jsx`）：建库、编辑、删除；条目带来源、版本、复核状态（未核对/已核对/已停用），改来源自动撤销复核状态。
- **知识导入**：指南/共识/资料文档批量导入，全文检索，按类型/集合/复核状态筛选，可带入任务。
- **知识自动整理**（0.9.66 根治预算问题）：批量上传文档/图片/音视频（PDF、DOCX、XLSX、MP3/MP4 等），后台转写 + 结构化整理；断点续传；限额可放宽（默认 100MB/200 万字符/200 份）。
- **知识地图**：主题/疾病/检查/治疗节点，点节点看原文行号或音视频时间点；关系默认"待核对"。
- **向量检索**：LanceDB 本地向量库，指南与患者材料分命名空间索引；嵌入三模式（免费云 API / 本地 / 关键词兜底），未配嵌入也能用。
- **检索出处**：知识库检索结果必须带原文出处与行号，供指南应用、决策流程图等技能引用。

## 八、科研与教学

- **文献检索**（`literature.jsx`）：查 PubMed / Europe PMC，仅查询词出网（病历原文不外传），结果可导入为会话材料（SHA-256 溯源）。
- **循证准备**（PICO）：编辑 PICO、检索式与核查计划，不虚构检索结果。
- **科研统计**（`research.jsx`）：会话 CSV 做描述统计、组间检验（Welch t、Mann-Whitney U、卡方、Fisher）、样本量估算、脱敏，纯本地确定性计算。
- **个案报告**：CARE 框架写作助手，患者脱敏。
- **DRG 估算**（`drg.jsx`）：单病例分组、批量 CSV 分析、本地权重/费率配置（内置简化 CHS-DRG 1.1）。
- **临床试验管理**（`trial-*.jsx`）：试验方案录入、入排标准拆分、确定性预筛 + 批量 AI 初筛队列、单患者 AI 逐条纳排（定位病历证据、冲突与待补资料）、拟邀请 → 联系 → 知情同意 → 入组流水线。AI 初筛只是草稿，不覆盖医生复核。
- **JEV 辅助核对**（可选）：外部校验服务，需填密钥并同意发送任务文本才启用。

## 九、通用 Agent 底座

与医疗无关的通用能力，独立可运行（`npm run platform`，端口 8788）：

- **本地工作区**（`workspaces.jsx`）：连接文件夹，浏览与检索文本，提出文件修改，查看 diff 并批准；目录外访问、密钥文件和符号链接受限。
- **开发工具**（`workspace-development.jsx`）：Git 分支/提交/远端、命令运行、冲突处理、AGENTS.md 项目说明。
- **执行能力**：终端（PTY）、Docker 容器终端、浏览器控制（独立审批、非持久化 Chromium 分区）、桌面控制、网页检索与正文抽取。
- **模型循环**：流式输出、停止、运行中追加要求、长上下文压缩与原文回查、轨迹回放、断点恢复、中断标记。
- **子代理与团队**：并行只读子任务；带文件作用域与依赖的异步多代理团队（`agent-team.mjs`）。
- **隔离执行**：JavaScript 工具编排（code-mode）、OS 级 Python 沙箱（macOS Seatbelt；不支持的主机失败关闭）。
- **计划任务**：单次/间隔/cron（含时区）调度，持久化队列，错过区间合并、失败暂停，独立于浏览器连接；后台守护进程（daemon）让任务在应用关闭后继续。
- **语义记忆**：持久语义记忆（latentSearch）+ 医生偏好记忆。
- **独立 CLI**：`npm run workspace --` 提供无需医疗服务器的命令行入口。

## 十、扩展生态

- **内置技能**（`skills/`，15 个，见下表）：可加载、可执行的领域工作流模板；技能不可执行任意命令（边界刻意收窄）。
- **扩展中心**（`extension-center.jsx`）：对话式让 AI 为医生自建技能/自动化规则（如"按我院模板写出院小结""HbA1c 高提醒我"），先试算预览、提案确认后生效，支持回滚历史版本。
- **MCP**：Model Context Protocol 客户端，配 OAuth 凭据保险库（密钥本地加密）。
- **插件**：受控离线插件包，下载校验；清单式聊天连接插件（manifestVersion/protocol，不执行脚本）。
- **Hooks**：工作区生命周期钩子。

## 十一、桌面端与运维

- **Electron 桌面壳**（`desktop/main.cjs`）：窗口/托盘/通知、屏幕捕获与权限请求；渲染进程禁代理、本地隔离；`npm run package:win` / `package:mac` 双平台打包，GitHub Actions 双平台验证构建。
- **macOS 原生四件套**（Swift 独立进程，最小权限）：本机 OCR（无截图权限、无网络）、系统控制辅助、文档扫描采集（VisionKit）、媒体处理（音频转 M4A、视频抽帧供 OCR）。
- **本机 OCR**：Windows.Media.Ocr / macOS Vision 本地识别，扫描件不静默外发；三级回退链（mac OCR → Win OCR → 视觉模型，低质量自动升级）。
- **PDF/办公文档**：浏览器端 PDF.js 解析（≤20MB/300 页，只存抽取文本不存原件）；办公文档取文（DOCX/XLSX 等）。
- **后台守护进程**：端口 + 指纹校验的 daemon 连接，应用关闭后任务继续。
- **Docker 运行时**：全功能镜像（Python/pandas/matplotlib + LibreOffice + tesseract 中文 OCR + poppler）供办公/数据任务沙箱；另有离线最小运行时镜像。
- **数据与备份**：`server/data/medical.sqlite`（WAL、0600、事务防并发覆盖）；`npm run backup` 一致性快照；schema 增量迁移（当前 schema 8+）；删除患者级联删除其工作区与记录。
- **验证工具链**：`npm run check`（lint+测试+构建）、`verify:model`（真实模型链路）、`verify:agent`（真实任务集）、`verify:desktop`、`verify:offline`、soak 长稳测试等。

## 十二、模型接入与数据安全

- **Provider**：DeepSeek / OpenAI / Anthropic / OpenAI 兼容 / OpenRouter / 本地 Ollama；多模型档案、上下文窗口与最大输出预算可调，页面显示实际生效值及来源。
- **密钥安全**：本地加密存储（`credentials.key` + CredentialVault）。
- **外发授权**：模型外发逐次授权；外发内容是原文（患者材料、消息或上下文），定时计划与随访自动总结需单独的重复外发授权；`reasoning_content` 与工具消息只留本机，不进导出。
- **材料边界**：每轮工具只读本轮选中材料范围；来源与页码/行号全程保留。
