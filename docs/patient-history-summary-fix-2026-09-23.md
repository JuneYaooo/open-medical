# 病史摘要字段与展示修复

版本：0.9.19。

问题：患者资料面板曾将通用 `note` 字段直接标为“病史摘要”。建档工具没有独立摘要字段，因此身份核对、OCR 冲突等备注被放到了病史首屏；这不是临床摘要。

修复：

- 新增 `clinicalSummary: { text, source }`，创建、更新、提案验证与确认持久化均支持；来源必填。患者速览向后续任务提供相同摘要。
- 建档 skill、运行提示和工具字段说明明确区分可读病史、疑似限定词、来源与资料备注。摘要先展示在建档核对页，确认后入档；更新提案对照前后内容。
- 现有档案缺少独立摘要时展示“病程概览”，直接按已保存就诊记录日期排列，不将任意备注充当病史，也不推断今天的病情。
- `note` 完整保留在可展开的“资料备注与待核对信息”。标签保持独立间距与换行。
- 没有改写现有患者诊断、日期、用药、原文或备注，没有把疑似复发/转移改成确诊。

验证：构建和 ESLint 通过；患者、临床字段、提案、资料面板与建档专项 42 通过、1 环境条件跳过；运行时专项 15 通过；上传—提案—核对—确认—摘要/备注分别展示的浏览器测试通过。桌面候选包完整性、签名、隔离运行与任务 smoke 通过。

安装后对现有档案只读核验：9 条就诊记录按时间排序，原备注默认收起但可完整展开；11 条诊断、7 条用药、16 条检验、36 份来源资料保留，页面错误和 API 写入均为零。安装 `/Applications/Open Medical.app` 并重启。
