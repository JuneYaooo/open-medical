## 浏览器人工流程

通过 Playwright CLI 在真实 Chromium 中运行桌面界面，使用临时 SQLite 和合成模型服务：

- 顶栏在「患者管理 / 资料工作台」间切换，患者管理为默认视图；
- 新建患者 → 自动进入详情；粘贴导入消息（「时间 | 患者 | 内容」格式）后在消息列表可见；AI 总结按钮在未勾选同意或未配置模型时禁用；
- 工作台导入 `output/playwright/synthetic-record.txt`，运行真实病历时间线得到来源事件；点击来源定位完整原文并高亮行（0.3 起不再有脱敏预览）；
- 提交复核者代号、核查说明、声明，状态变为“已复核”；修改产物要求修订依据，版本增加且状态回到“待复核”；
- 在模型模拟服务中完成慢流；点击停止后为“已停止”，没有假助手结论且可载入原任务重试；
- 会话切换时用当前会话 ID 和 revision 防止旧流写入另一病例；材料检索只命中当前会话；桌面页面无横向溢出；
- 三个子代理联合整理、隔离计算、计划任务的暂停/恢复沿用 0.2 已验证路径。

截图与合成输入保存在 `output/playwright/`，不应被当作产品数据。

## 仍需单独验证

配置所选 Provider 的真实密钥后运行 `npm run verify:model`；它只发合成工具调用内容。需要进一步人工确认模型选择、实际费用、请求配额、外发合规和响应延迟。建议先使用合成数据验证。沙箱当前只有 macOS 后端；RSS 内存监测为采样而非硬配额；调度与随访需要本地服务运行，尚无 cron 表达式、系统唤醒或任务依赖图。患者管理的微信 CLI 桥接只验证了 HTTP 契约（ingest 密钥、去重、归属），未验证任何具体第三方 CLI 的对接。

部署到真实机构前还必须完成：威胁建模与渗透测试、磁盘/备份加密、多人身份和权限、不可篡改审计、密钥轮换、数据保留/删除政策、HIS/EMR/FHIR 映射、OCR 和原件留存策略、药物与指南知识库、临床专家标注集、漏检/误检评估、可用性和灾备演练。当前代码没有声称完成这些工作。
