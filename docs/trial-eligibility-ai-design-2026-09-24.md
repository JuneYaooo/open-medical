# 临床试验自动纳排：需求依据、实现与验收

## 目标

医生选择患者和一个已保存的试验方案，Agent 自动读取患者档案、病历资料，对全部纳入和排除条件给出有出处的初筛草稿。医生先处理冲突、补齐缺失资料，再查看全部条件及原文，最后独立保存核对记录。此次实现不是只跳转聊天或预填提示词。

## 调研依据与产品取舍

未进行医生访谈；下列需求来自官方流程、研究论文及开源实现，页面方案是结合本项目使用反馈作出的设计判断。

| 实际问题 | 资料依据 | 本项目的处理 |
| --- | --- | --- |
| 试验匹配需要知道具体哪一条满足、冲突、缺什么，仅相似度难以支持核对 | NIH/NLM [TrialGPT FAQ](https://www.ncbi.nlm.nih.gov/research/trialgpt/faq/) 描述支持证据、潜在不兼容项与缺失信息的结构化解释 | 默认先看“冲突与待补”，展开病历原文；另有全部条件视图 |
| 候选检索与具体资格判断是两个步骤 | [TrialGPT 开源实现](https://github.com/ncbi-nlp/TrialGPT) 分为检索、逐条件匹配、排序 | 本次先把指定方案与患者的逐项纳排做通，不以检索排序代替判断 |
| 病史、既往治疗、分期、分子特征影响筛选；地点与时间安排也影响参与 | [NCI 查找试验流程](https://www.cancer.gov/research/participate/clinical-trials-search/steps) | 保留方案来源、版本、研究中心与招募状态；AI 核对资料，中心名额和参与意愿仍待研究团队确认 |
| 旧病历与更新后的方案会影响初筛可信度 | [NLM FAQ](https://www.ncbi.nlm.nih.gov/research/trialgpt/faq/) 要求核对当前记录、招募及队列/中心信息 | 方案保存为固定版本；患者档案修订或材料清单变化后结果标为过期，不能直接采用 |
| 缺资料不能直接排除患者，也不能视为满足 | TrialGPT 的逐条件输出及 NLM FAQ 对不完整资料的说明 | yes/no/unknown 分开；排除 yes 表示触发排除。缺失项必须写具体待补内容 |

没有直接接入 TrialGPT 公共网站，也没有向它发送患者资料。借鉴的是公开工作流，执行继续使用本项目当前配置的模型与 Agent 内核。产品宣传的效率数字不作为本项目效果承诺。

## 页面

1. **试验方案**：保留上传方案、注册号读取、来源和版本。上传后明显的纳排标题可自动拆分；复杂队列方案尚需核对条件，不声称已经实现任意方案自动结构化。
2. **AI 自动纳排**：选择患者后，一键开始。明确提示资料交给当前配置模型；显示已完成条件数、运行状态，可停止，可离开页面。
3. **结果重点**：三个数字为条件冲突、待补资料、已有依据支持。不是概率分数，不自动宣告可入组。每项展示条件、判断、简短原因、资料日期、缺失事项、展开的引用原文及文件行号。
4. **医生核对**：默认折叠，AI 草稿与人工记录独立。“带入医生核对”后可修改、保存，保留人工记录版本。

患者未变化也允许重新初筛：同一患者/方案只允许一个运行中任务。失败、停止、重启中断都保留已有判断；重新初筛生成新任务，不冒充完成或覆盖人工记录。

## Agent / Skill / Tool 连接

- `skills/trial-eligibility/SKILL.md`：专用技能。说明入排极性、AND/OR 与队列例外、检查时间窗、用药线数与洗脱期、知情同意未知项等。
- `TrialEligibilityJobs`：SQLite 持久任务，固定患者和方案版本；通过已有 `WorkspaceService` 启动独立医疗会话，不复用旧聊天上下文。
- `configureTrialTools`：该任务仅开放阅读/检索资料、读取技能、按行读取方案、保存纳排批次。不能写患者档案、运行代码或随意联网。
- `read_trial_criteria`：下一批最多12条条件，以及方案版本、筛选日期、研究中心信息。
- `read_trial_protocol`：读取方案上下文，核对分组及例外。
- `save_trial_eligibility_batch`：校验固定条件 ID、患者会话、已读行范围、逐字引用。yes/no 没有来源无法提交；unknown 必须有具体缺失项。逐批持久化，全部完成只生成一份结构化草稿。
- 终止沿用 Agent 的可信结果收束机制：交付后直接渲染已保存结果，不再调用模型重复“重新核对”。无完整草稿即失败，不因模型声称完成而显示完成。
- 医生记录由原保存接口独立处理，乐观版本锁与审核历史保留。

引用校验证明引用存在且本轮读过，不证明模型的临床解释正确；需研究团队复核。现有验证并不构成临床性能验证。

## 当前边界及后续方向

本轮交付为“一个患者 × 一个已选方案”的自动逐项初筛。院内批量患者队列、一个患者自动匹配整个试验库、中心实际名额接口、任意复杂 PDF 条件结构化是后续独立能力，不包装成已实现。

建议下一阶段：先建立科室实际开展的试验库，标清队列、中心、更新日期和联系人；再做批量初筛工作队列，按明确冲突/可补资料/可交研究者分类，不以黑盒概率排名。资料新增触发重新核对可后续接入事件调度，当前只标记过期并提供重新初筛。

## 验收

- 合成患者 API/Agent 测试：已读出处、无来源拒绝、缺失与排除区分、重复启动、跨患者取消拒绝、停止后迟到结果、人工记录不被改写。
- 真实配置模型，仅发送合成患者：3条条件自动核对，年龄满足、7天内肝功能缺失、另一干预试验触发排除；7.1秒完成，预期结果全部一致。
- 浏览器：离开再返回查看后台结果，切换重点/全部条件，展开原文，将草稿带入人工核对并保存；宽屏与窄屏验证。
- 完整回归与桌面验收结果在本次交付时补记。
