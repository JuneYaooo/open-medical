# 全局聊天 Agent 底座与患者自动分组 · 0.9.88

日期：2026-10-10。本轮为功能清单 P0 主线：全局聊天 Agent 底座 + 患者自动分组（后者为前者的第一批落地能力）。全部使用合成患者与隔离数据库验证；无真实患者资料，无对外发送。

## 交付范围

- **全局助手会话（单例）**：`POST /api/assistant/session` 幂等查找或创建一个常驻 `kind:"session"` 工作区（`modeFlags.global`），不关联单一患者；侧边栏「医疗工作 → 全局助手」入口复用既有任务会话页，聊天循环、@患者 提及、流式渲染零改动复用。上下文默认链式继承（非患者会话默认行为），每条消息一个 run，运行策略固定 `workflow=global-assistant`、问答式交付、限额（40 轮 / 80 次工具 / 8 分钟）；拒绝其他工作流路由到全局会话。
- **收窄的跨模块工具面**：全局运行只注册 `list_patients`（姓名→编号解析，同名列出供选择）、`read_patient_chart`（跨患者只读档案速览，与患者简报同源）、`patient_scan`（确定性花名册扫描）、`followups_overview`、`patient_grouping_propose`，并复用既有会话插件的 `knowledge_collections` / `knowledge_search` / `followup_create_propose`。不注册病历整理、治疗方案评估等工作流工具；系统指令换用全局助手纪律（写入只走提案、同名患者须让医生澄清、证据不足如实说明）。
- **确定性患者扫描**（`server/medical/patient-scan.mjs`）：把分组意图转成结构化条件一次遍历全部在管患者，不逐患者调用模型。条件：诊断关键词 + 日期窗口（如「术后三个月内」）、就诊事由 + 窗口、检验阈值 + 窗口（如 HbA1c > 7 且 90 天内，仅数值比较）、标签 / 分组 / 性别 / 年龄段。命中带逐人依据行，上限 100 条并标记截断。
- **患者分组提案**（`patient-grouping` 待复核类型）：`patient_grouping_propose` 生成提案（组名 ≤40 字、1–100 位患者、逐人分组依据必填、快照姓名与当前分组、`sourceSessionId` 可追溯）；医生在「待确认」托盘核对（展示每位患者依据与已分组）后确认。确认在单事务内逐患者合并分组（`patients.update` 带当前版本乐观锁）：已在组内幂等成功，归档或分组数已满 10 的逐人跳过并在结果说明，个别患者漂移不推翻整份提案。
- **联动**：患者列表按组筛选（既有能力自动生效）；今日待办新增分组筛选（`/api/doctor/overview?group=`，仅保留该分组在管患者的事项，与患者无关的通用事项在筛选时隐藏；前端下拉选项来自在用分组）。

## 设计要点

- 复用统一内核（WorkspaceService + AgentRuntime），不新建引擎：全局会话即普通会话工作区 + `modeFlags.global` 标记；工具面切换沿用「运行策略决定工具集」的既有模式（与 patient-assessment / trial-eligibility 同构）。`contextIdentity` 包含 `systemFor` 输出，标记切换自动失效旧上下文复用。
- AI 不直写底线不变：全局助手唯一写路径是 pending_actions 提案 + 医生确认；扫描、档案读取均为只读。
- 扫描是确定性本地代码：模型只负责把自然语言意图转成结构化条件并解读结果，成本、可审计性与红线规则同一量级。

## 验证

- 新增 `tests/global-assistant.test.mjs`（5 项，全部通过）：
  1. `patient_scan` 匹配器——诊断/检验/年龄/分组条件、多条件同时满足、归档跳过、依据行文案、非法条件拒绝；
  2. `patient-grouping` 提案生命周期——快照、去重、缺依据拒绝、确认合并保留既有分组、重复确认 409、幂等 `already`、提案生成后归档逐人跳过、拒绝不生效；
  3. 全局助手全链路（合成脚本模型）——单例会话、`modeFlags.global`、工具面含扫描/分组提案/知识库且不含病历整理工作流、`patient_scan → patient_grouping_propose → 医生确认 → 患者入组` 全链路、提案可追溯到全局会话、跨 run 上下文继承、其他工作流被拒绝；
  4. 今日待办分组过滤——只保留该组患者、隐藏无关通用事项、不存在分组为空；
  5. 领域分支——全局会话换用全局纪律（不含病历整理文本）、普通患者会话与项目工作区不受影响。

## 边界

- 本轮全局工具面刻意收窄（查患者 / 知识库 / 随访 / 分组提案）；知识库写入、统计、群发等后续迭代再挂载。
- 分组为纯字符串分组（沿用既有模型，无分组表）；企微群发按患者组筛选不在本轮（群发面向企微客户群，概念不同，后续单独设计）。
- 「术后三个月内」等时间窗口依据诊断/就诊日期字段，档案缺日期时不命中并如实说明，不推断。
- 真实模型链路（自然语言 → 结构化条件的转换质量）未在本轮验收，合成脚本模型只验证工具编排与提案链路；配置真实密钥后按 [医生使用指南](DOCTOR_WORKBENCH_GUIDE.md) 流程复验。
