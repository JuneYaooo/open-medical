# 患者问答动线与上下文边界

## 交互约定

- 从患者页进入病例问答，或从首页选患者发起任务、从诊疗辅助准备问题：独立开始新问题。
- 已完成回答下的输入框默认继续这段问答，并显示原始问题作为提示。
- “问新问题”和“以前的问答”固定在问答区顶部，长回答滚动时仍可使用。
- 历史问答只在主动选择后展示；可以回到一个旧问题继续追问，不混入中间的其他问题。
- 切换问题时保留本页未发送的输入。刷新或关闭页面不承诺保存未发送草稿。
- 执行中的补充要求仍走当前任务队列；执行期间不能切换问答。
- 未完成或本地规则回答不自动作为模型追问上下文，界面说明再次发送会独立开始。
- 普通患者问答不显示建档流程步骤条。患者档案和资料仍为共享资源。

## 实现

每轮记录 conversationParentRunId；未指定父问答的患者模型任务默认隔离聊天历史，包括直接调用工作区 API 的情况。父问答必须属于同一工作区、已完成且满足当前权限及模型上下文身份。普通非患者任务保持原有行为。

追问从指定问答链的可见用户/助手消息重建上下文，不复用旧 provider 检查点，避免旧版本混入的其他任务继续传播。旧任务没有父关系时按独立问题处理。重试未完成任务的检查点恢复仍保留原有语义。

患者当前事实通过 read_patient_brief 读取，所选资料由当前材料索引与检索工具提供。聊天历史不是患者档案；删除或更改问答展示不修改档案。历史结果仍是待核对资料，不能自动覆盖最新档案。

## 验证

- API：新问题隔离、指定旧问题追问、连续追问、跨患者拒绝、失效父问答拒绝、旧检查点污染隔离。
- 浏览器：患者页进入、新问题、连续追问、历史切换、重新打开、切换患者。
- 保持普通会话、患者工具、桌面独立数据冒烟检查。
- 相关测试：tests/patient-conversations.test.mjs、tests/patient-conversations-ui.test.mjs。

## 桌面版本保留规则

用户要求只保留最新版。每次更新必须先完成候选包验证、安装、启动及更新前后数据核对，再清理旧应用、临时回滚副本和重复打包目录。唯一安装位置为 /Applications/Open Medical.app。

清理仅限确认属于本项目的构建产物。不得删除患者数据库、知识库源文件、用户上传资料或代码；更新未成功时先恢复可运行版本，不提前删除回滚副本。
