# 0.9.8 代码复核

范围：2cb3182 → 798cd75。审查时工作区干净；本轮未修改产品代码。以下不是全量审计，重点检查本次新接入的运行与评测路径。

## 结论

通用入口与跨平台边界有实质进展，但交付验证未贯通主执行路径，评测器存在隔离和误计通过的问题。当前不宜用其通过率作为能力认证依据。应先修评测可信性，再跑真实模型基准。

## 确认的问题

### R1 / P1：验收器在宿主直接执行被测代码，隔离失效

位置：scripts/eval-v1/validators.mjs:118—146。

runNode 使用 spawn(process.execPath, ...) 导入模型生成的模块，继承仓库 cwd、环境和宿主权限，没有受控执行后端，也没有子进程截止时间。即使 Agent 工具本身受工作区约束，验收阶段仍可越过该约束。

无害合成探针已经证明：price.mjs 能从仓库读取 evals/general-agent-v1/cases.json 的 oracle，将可访问性写到测试工作区，然后数值断言正常通过。没有读取任何真实秘密。错误生成的无限循环或残留定时器也可使验收一直不结束。

建议：生成代码在隔离后端执行，只挂载被测材料；评估控制器、答案和宿主环境不对其可见，另设进程期限和进程树清理。单独改 cwd 不能构成隔离。

验收：读答案/工作区外合成诱饵被拒；无限循环按时终止；合法正确解仍通过。

### R2 / P1：必需检查 blocked 仍计为 pass

位置：scripts/eval-v1/validators.mjs:103、425—485；run.mjs 汇总按顶层状态计数。

S04 返回缺少独立重算引擎的 blocked，D01 返回缺少版式渲染的 blocked，但 finish 无条件返回 status:pass、pass:true。运行器使用该状态计数，blocked 只是附带文字。

已运行 S04 合成探针，实际结果同时出现 pass:true 与 blocked:[独立电子表格引擎重算…]。这与数据集的必要断言全部通过才算成功冲突。

建议：检查项区分 required/optional，任一必需项 blocked 时整项不能 pass；部分结构检查单独记录成功。补充报告汇总回归测试，不仅测试单个断言。

### R3 / P1：通用工作区没有接入交付验证

位置：server/core/workspace-service.mjs:2080—2133；AgentRuntime 的新 onDelivery 为可选接口。

实际通用执行未传 onDelivery，且完成落库丢弃 result.delivery/outcome；状态和通知仍直接写 completed。SessionBridge 新字段投影无法补出从未写入的事实。

已使用脚本模型返回“报告已写入 report.txt”，没有调用任何工具。WorkspaceService 返回 completed，delivery/outcome 均为空，文件未创建。此项是既有缺口在本次新交付接口后仍未闭环；任务账本已部分承认，但不能把 W5 服务端整体视为完成。

建议：接通主执行路径的任务类型、目标与产物核对，持久化并传播实际结果；普通问答允许无工具完成，执行任务缺少要求产物应继续验证或报告未完成。

### R4 / P1：医疗路径把任意副作用当成完整交付

位置：server/runtime.mjs:718—739。

effects 包含 delegatedReceipts.length>0；子代理结束后无论状态是否 completed 都加入回执。随后 if(effects) 直接 delivered:true。因此全部子任务失败且没有产物，也会被标记已交付；完成了与目标无关的沙箱操作同样足以通过。

这是新增逻辑中的静态确定分支，本轮未执行该医疗委派场景。应按用户要求逐项核对必要成果，失败子任务回执不能充当成功证据；有回执只是发生过动作，不代表完成目标。

验收：子任务全部失败时不交付；只完成多项要求之一时显示缺口；全部必要成果验证通过才 delivered。

### R5 / P2：真实评测入口不加载已保存模型配置

位置：scripts/eval-v1/run.mjs:196—200；对照 scripts/verify-model.mjs 的 discoverModelConfig。

运行器直接 createProvider()，没有加载仓库 .env 或桌面 model.env；provider 工厂仅读取进程环境。verify-model 在另一个进程加载配置并不会传递给后续 node run.mjs。因此只按账本说明将凭据放入配置文件再运行评测，仍会报告未配置；只有预先导出进程环境等额外步骤才可用。

建议：共用模型配置发现模块，并测试仅有桌面保存配置/仅有 .env 的独立子进程启动，不输出密钥。

### R6 / P2：多轮评测记录仍关联首轮，预算按轮重置

位置：scripts/eval-v1/run.mjs:351—380、后续 toolTraceOf/tokens 读取。

T01/T03 与 A01 后续轮更新 run 与 finalAnswer，却没有更新/聚合 runId；最终产物是后续轮，轨迹和 tokens 则读取首轮。同时每次 runAgent 都重新给完整600秒/80轮，不能落实“每个任务一次运行”的统一预算。

建议：记录整项的所有 runId，聚合轨迹、token 和副作用；整项共享剩余截止时间与调用预算。测试第二轮新增一次工具动作时，它必须出现在正式结果中。
