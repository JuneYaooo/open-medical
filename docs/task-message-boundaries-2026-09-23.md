# 患者任务消息边界修复（0.9.26）

问题：同一患者复用病例工作区，页面直接展示工作区全部 messages，并统一标记“本轮输入”，导致不同运行的提问和回复连续混排。检查实际记录后确认消息有独立 runId，未发生存储合并。

修改：患者任务正文只展示最新运行的消息（含同一运行的补充要求）；历史任务入口打开执行记录，各运行可独立展开自己的完整对话。未关联患者的普通会话保留连续对话。历史记录不删除。

同步修复：answer 完成要求在存在真实产物回执且无缺口时应允许判定交付，原实现无条件判失败。对既有已完成医疗评估/相似病例记录，仅在旧错误恰为 no_verifiable_output 时重新核验运行事实后投影正确状态，不改原始审计记录；真实工具失败仍保持失败。交付草稿不代表临床复核通过。

验证：7 项聚焦工作流测试及 48 项通用交付/桥接回归通过；新增断言覆盖旧错误重验、保留审计、真实失败不被掩盖。浏览器验证当前提问与回答不包含旧消息，历史对话可展开，旧失败可追溯，本次失败仍显示。lint、前端构建通过。
