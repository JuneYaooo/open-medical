# 业务导航与阅读体验改造验收

日期：2026-09-22；桌面版本：0.9.17。

依据 `product-ux-implementation-plan-2026-09-22.md` 与 V5 原型，先落实业务导航、页面分层和阅读字号。继续使用真实领域数据及现有运行内核，不引入原型的模拟数据。

## 本轮实现

- 默认打开患者列表；一级业务导航为患者、随访、科研。保留 AI 工作台及可展开的任务、项目、工具、医生记忆入口。
- 患者详情分为患者档案、沟通与随访、诊疗辅助。默认展示连续可读档案，AI 简报和处理步骤放入诊疗辅助。保留临床资料编辑、来源、风险、消息、随访、检查与转诊。
- 随访默认展示待办和结果记录；模板、排程配置在计划与模板中。沿用真实状态，不将未发送任务标记为等待回复。
- 使用系统中文无衬线字体；病史正文 18px，大字模式 22px；按钮和表单控件至少 44px，字号偏好刷新后保留。患者列表返回位置保留，窄屏调整为单栏。
- 启动时等待能力配置，再挂载患者页面，通用工作台不请求医疗接口。
- 既有上传自动解析、后台任务、失败恢复、确认入档和模型运行机制保留。

## 验证记录

- ESLint、前端构建、git diff whitespace 检查通过。
- 新增业务导航、默认首页、字号持久化、患者三个栏目、随访分层及窄屏测试。
- 全量测试 778 项：755 通过、21 项按环境跳过、2 项旧消息导入导航选择器失败。修正测试为先进入沟通与随访后，浏览器和 Electron 两项均通过；另重新运行完整 redesign 浏览器与桌面场景集，43 项全部通过，报告见 `output/business-layout-redesign-final.log`。
- 启动隔离专项 4 项通过，包含通用工作台创建、执行、产物及继续任务闭环。
- 桌面候选包源码一致性、签名、隔离数据库、渲染器隔离、实际任务草稿生成及 sandbox smoke 均通过，见 `output/business-layout-desktop-final-report.json`。
- 安装并重启 `/Applications/Open Medical.app`。安装后对现有患者进行只读检查：11 条诊断、7 条用药、16 条检验、9 条就诊、36 份来源资料；无页面异常，无 API 写入。见 `output/business-layout-installed-report.json`。

## 实施边界

本轮落实前端信息架构与阅读体验，不代表整份产品方案完成。AI 三种显示模式、统一患者事件模型、研究项目与队列、微信自动化业务闭环仍按方案后续实施。科研入口继续使用已有真实分析功能。
