# 医生工作台 8 小时自主优化计划

执行窗口：2026-09-22 00:47–08:47（Asia/Shanghai）；对应 UTC 2026-09-21 16:47–2026-09-22 00:47。上一轮改动保留为起点，不覆盖或撤销。首批用户暂按单医生、门诊与慢病连续管理；如果用户补充专科，按反馈调整。

## 成功标准

医生首次打开时能识别“今天处理什么”；查看一位患者能迅速找到已知事实、缺失资料、待处理事项；一次资料整理能接续文书、复核、随访，不重复解释背景。通用 Agent 的工具权限、上下文、恢复和交付质量不因医疗层退化。

每个功能必须有真实数据链路、失败反馈和可回读结果。公开调研用来提出假设，不声称已经完成真实医生访谈或证实临床有效性。用合成患者和隔离数据库验证，无需访问真实患者资料。

## 八小时安排与优先级

| 时段（相对开始） | 目标 | 交付与验收 |
| --- | --- | --- |
| 0–0.75 小时 | 官方资料调研、代码与风险基线 | 有来源的痛点矩阵、场景脚本、优先级；先修复患者导入索引外发与身份歧义等已证实基础问题 |
| 0.75–2 小时 | 今日工作与患者优先队列 | 汇总待复核、待联系、未处理消息、风险和失败项；明确下一步；真实浏览器验证“打开即开始” |
| 2–3.5 小时 | 患者纵向视图与接诊准备 | 事实来源、信息缺口、近况、同名识别、近期记录；生成携带当前患者上下文的任务草稿 |
| 3.5–5 小时 | 知识治理与诊后复用 | 来源/版本/复核信息、检索过滤、可复用诊后输出；减少重复填写和页面切换 |
| 5–6.5 小时 | Harness 与负载、故障验证 | 实际工具任务、持续负载、取消/恢复、数据一致性、容量测试；保留失败轨迹 |
| 6.5–8 小时 | 端到端验收与体验打磨 | 首次使用、完整患者任务、空/错/冲突状态、键盘与窄屏；全量回归、构建和最终证据 |

时间表是投入分配，可依据发现调整；不为凑时长重复运行相同测试。后台持续负载需要隔离冻结源码，以免把开发期间混合版本当成单一版本验收。8 小时不能证明 48 小时稳定性。

## 取舍

- 本轮优先持续管理和减负；不自行扩张为自动诊断、处方、患者消息自动发送或 HIS 全替代。
- 同时保证一般研究、文件、浏览器与终端任务仍可从通用 Agent 入口执行。
- 临床规则采用有来源的有限提示；缺失信息不得被补写成临床事实。
- 修改生产配置、替换已安装应用、发布等不属于默认交付动作；可构建独立候选供检查。
