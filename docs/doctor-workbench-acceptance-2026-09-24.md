# 医生工作台迭代验收 · 0.9.38

日期：2026-09-24。所有自动化写入使用隔离数据库。真实患者桌面仅做只读核对；没有向患者发送消息或改写已有患者档案。

## 交付范围

- 医疗业务导航：患者、随访、临床试验、知识库；原统计能力留在工具中。
- 患者：卡片列表、六个临床页签、简化概览和诊疗辅助入口、大字阅读；保留原文及核对状态。
- 任务：普通问答与相似病例/文献/计算器/辅助诊断分开展示；历史任务和执行记录收进次级入口，材料检索不再额外制造待复核产物。
- 随访：临时联系、联系方式、症状/实际用药/检查反馈/下一步安排；按联系结果筛选；按患者调整模板节点和日期，重复提交不会重复创建提醒。未联系上不能保存为已核实临床反馈。
- 临床试验：方案上传、清晰中英文标题下的条件解析、NCT 注册资料读取、国内注册平台原站入口、患者逐项初筛、证据与缺失项、独立草稿和历史。复杂多队列不会自动压成一套条件；年龄和性别注册字段保留，正式入组由研究团队判断。
- 知识库：独立分库，必填内容说明与使用场景，可写限制；多格式资料导入及本地 OCR；关键词/语义索引状态分别显示；指定库未命中不会自动跨库；长段落分块不丢文档后半部分。

详细调研、逐模块建议与官方数据来源见 [产品调研](doctor-workbench-research-and-iteration-2026-09-24.md)。参考的是公开产品及机构资料，没有将其表述成医生访谈或临床有效性研究。

## 本轮测试发现并修正的问题

1. 模型口头说“文件已创建”但没有真实产物时，统一会话内核未明确显示失败。显式文件/报告要求现在核对本轮回执；普通回答不强制变成文件。
2. 相似病例和治疗评估已保存结果后，还多请求一次模型收尾；空返回会把已有成果的任务标为失败。改为从当前已保存草稿直接形成答复，仍经过执行与交付核验；较晚追加的用户要求不会被旧成果吞掉。
3. 相似病例自由概括把候选的治疗经历写成双方共同经历。改用逐项、分清双方的事实构成摘要；引文按已读取原文核对，支持排版空格及 HTML 显示归一；错误对照最多要求一次纠正，其余缺口明确保留且不评分。
4. 对原文明示未确定的分期、未确认的用药状态，降低为未知，排除出评分。显示加权覆盖率；疾病不同仅作为文献线索展示，不显示相似患者分值。
5. 知识库长单段文本原先可能只嵌入前半段，现按字符分块；语义失败不再伪装为已建好索引。
6. 关闭资料侧栏后的通用项目半屏布局、已填写文本框的无障碍标签、全量测试过度并发导致的磁盘压力，一并修正。

## 已知边界与后续建议

- 企业微信没有真实企业账号和回调环境，本轮没有声称验证实际送达、身份绑定或患者回复回流。
- 试验模块可读取指定 NCT 和核对本地方案，尚未实现国内各注册平台的统一自动检索，也不自动申请入组。
- 知识库保存的是抽取文本、版本和来源信息；扫描件质量影响 OCR，原始医学信息仍需核对。语义检索依赖已配置的嵌入服务，未连接时关键词检索仍可用。
- 试验未保存草稿目前支持同一页面来源下的患者切换、导航和刷新恢复；退出桌面软件前需点击保存。正式保存的方案与初筛记录存于数据库。跨启动的未保存草稿同步可作为下一轮改进。
- 桌面停用期间不会假装实时联系患者。跨设备、多人协作和连续后台服务另需部署与验收。
- 构建存在已有的大资源块提醒，功能构建通过；后续可继续拆分非首屏依赖以优化首次加载。
