# 患者方案评估执行与交付修复（0.9.22）

问题：患者治疗方案评估继承了已反复压缩的旧任务上下文；医疗读取未进入运行时证据记录；检索、用药核对等中间产物都计入待复核。结果是重复读取、重复开场、产物堆积，前端目标卡还把其他运行的产物当作完成证据。

修改：

- 已关联患者的治疗方案合理性问题进入独立评估流程，保持当前患者及选中资料，不继承旧运行的执行历史。
- 暴露 10 个相关工具；最多执行 18 次资料核对操作（其中外部文献检索最多 2 次），随后只保留草稿工具。总轮数、工具次数和 8 分钟执行期限另作硬边界。
- 患者档案和病历片段进入运行时读取记录与原文归档。出处必须来自所选患者资料且在实际读取范围内；无法验证的出处被拒绝。
- 只收集治疗评估草稿；同 ID 不重复写入。草稿落库后关闭工具阶段。最终回答由已保存草稿的结构化字段生成，避免拼接中间独白。没有带出处草稿时明确失败，不显示评估完成。
- 评估执行独白默认折叠；目标卡仅使用最新运行产物，计算原文出处，人工复核与执行结束分开。
- 失败、取消、中断运行的草稿可收起并恢复。保留原文、产物、原复核状态和运行记录；已复核产物不受影响。

验证：

- 50 项相关后端回归通过（患者上下文、运行证据、会话桥接、上下文预算、领域适配等），ESLint 与前端构建通过。
- 使用正式病例的只读副本、内存数据库和当前配置模型验证，不向正式患者写入测试草稿。完成三次真实模型复测，约 101 / 91 / 97 秒，均只生成一份带出处草稿；最后一次包含 5 处来源。
- 浏览器隔离验证：结构化标题、目标出处计数、失败草稿收起/恢复、运行说明默认折叠并可展开通过。
- 桌面候选包单独执行内容一致性检查与隔离启动 smoke；实际安装状态见此次交付记录。

范围：上述测试证明执行能终止且交付结构化草稿，不证明模型医学结论正确。模型可能将“未读取/未记录”误判为“临床未做”；工作流明确提示区分，并始终保留人工复核。知识库缺失、当前治疗状态不明时应输出有限评估和缺口。
