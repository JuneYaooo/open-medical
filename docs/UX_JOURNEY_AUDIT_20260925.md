# 全动线 UI / UX 审计与优化 · 2026-09-25

> 验证包含真实服务、隔离桌面实例和受控接口测试。各业务链路的验证方式与限制分别列出，不代表所有外部环境均已验证。

## 审计判断

项目以患者、任务、项目三种工作对象组织主要功能，患者建档 → 材料整理 → 来源复核 → 后续随访的主结构合理；通用 Agent 能力也有独立项目入口。主要不足集中在跨页面状态连续性、失败恢复、列表完整性和输入与输出的一致性。此次保留现有视觉风格和功能结构，针对有复现依据的问题改动。

优先处理的是会让用户判断错误或丢失工作的交互：患者打开失败却提前切换身份、部分随访被截断、请求失败看起来像没有患者、输入已变而结果仍沿用旧值，以及离开首页丢失草稿。视觉调整服务于这些问题，包括空状态入口、危险操作的识别和加载反馈。

## 已修正的问题

| 动线 / 问题 | 修正 | 验证依据 |

| 主导航只改变内存状态，地址栏不更新；刷新回到起点，前进后退不可用 | 建立页面路由、患者/任务/项目 ID 和有效页签恢复；浏览器返回前进恢复页面；标签页标题标明所在功能 | `navigation-recovery-ui.test.mjs` |
| 患者详情刷新丢失正在查看的页签 | 恢复患者 ID 和档案页签；返回列表移除详情定位；非法页签回退到有效页面 | 同上 |
| 项目面板刷新回到默认文件页 | 记录当前项目与工作面板，刷新恢复 | 工作区与项目回归 |
| 首页写到一半去看患者，回来丢失文字与附件状态 | 在当前应用会话内保留首页草稿、所选患者、技能和待发送附件；明确新建任务后才清空 | 草稿跨页面测试 |
| 在项目或工具深链接上首次连接失败，没有统一恢复入口 | 所有业务页面等待运行时连接；失败后提供明确错误和重新连接按钮 | 首次连接失败注入 |
| 列表请求失败被当成零条数据，已有列表消失 | 分项加载，保留上次成功数据，说明哪些列表没有更新，提供重试 | 患者列表失败注入 |
| 患者空列表只是提示文字；已归档空列表文案不准确 | 区分初次使用、无搜索结果和无归档患者，提供建档、手动填写、清除筛选和返回在管入口 | 桌面 / 窄屏截图 |
| 打开患者前先切换全局身份，失败时身份与档案可能不一致 | 数据成功读取后才切换身份与页签，并显示打开进度 | 患者切换与失败回归 |
| 未来随访仅展示前 20 项，后续计划无法操作；后端总览也固定截断 | 增加“显示更多”，后端提供稳定排序、offset、总数与 hasMore，界面读取完整分页 | 23 项跨患者 UI 测试；API 分页测试 |
| 未来随访没有直接打开患者入口 | 增加打开患者，并落到该患者随访页 | 随访到患者回跳 |
| 随访删除按钮立即删除，难以核对目标 | 展示患者与计划名称的确认框，可取消；模板删除说明已有患者计划保留 | 删除取消与确认测试 |
| 文献摘要请求失败后永久显示加载中 | 摘要内部显示失败原因并允许重试；不必重新搜索 | 外部服务失败模拟 |
| 连续点击文献导入可能创建多个任务；失败重试另建任务 | 导入中禁用操作并拦截重复请求；同次页面内重试复用已创建的目标任务 | 连续点击导入验证；真实联网导入 |
| DOI 链接统一标注“在 PubMed 打开” | 按实际目标显示 PubMed 或 DOI 来源 | 页面检查 |
| 切换科研数据任务时慢请求覆盖新任务文件列表；错误未捕获 | 清理旧选择、显示材料加载中，以请求版本丢弃过期响应，显式显示错误 | 人为延迟交叉请求 |
| 量表、样本量、统计检验、DRG 输入变化后继续显示上一次结果 | 修改输入时清除旧结果，处理中限制修改相关输入 | 量表 / 样本量输入回归；既有计算流程 |
| 浏览器预览导航失败仍展示上一页截图 | 新导航清理旧截图与内容，避免把旧画面称作当前页面 | 代码检查与工作区回归 |
| 媒体切换操作/内容后旧结果和授权状态残留 | 清理旧结果和对应内容授权；相同文件可再次上传 | 工作区面板检查 |
| 模型设置读取失败无重试，测试按钮绕过必填校验 | 增加重新读取入口；测试前执行与保存一致的原生表单校验 | 设置专项 / 实际模型连接 |
| 医生偏好保存失败会覆盖未保存文本；记忆操作重读时也覆盖编辑 | 失败保留文本，明确“放弃未保存偏好并载入最新配置”；刷新记忆时保留编辑；旧记忆查询不覆盖新页签 | 失败后重试保存测试 |
| 删除图标继承红底又使用红色前景，对比不足 | 改成浅色/透明背景与深红图标，保留明确危险操作样式 | 随访确认框与列表截图 |
| 部分工具页面“跳到工作区”找不到目标 | 增加所有页面共有的内容焦点目标；补全文献、病例、科研、DRG 输入的可访问名称 | 全页面可达性扫描 |

## 范围与仍需外部环境的项目

1. 当前验证平台为 macOS；Windows 实机、另一台干净 Mac、睡眠唤醒等未验证。
2. 微信 / 企业微信真实联系人收发、外部 OAuth 登录、付费媒体服务和远程 Git 托管提交，需要相应测试账号、目标与授权。本轮不向真实患者或他人发送消息；这些入口仅能验证本地 UI、权限拒绝和受控接口流程。
3. 真实病历外发未执行；模型验证仅使用合成患者和合成材料。模型实际回答质量、医学有效性与机构部署验收不由 UI / UX 测试替代。
4. 本轮的首页未发送草稿保存在当前应用内存，跨页面保留；关闭应用或整页刷新不会自动持久化未发送正文。已上传材料保存在本地任务中。临床试验草稿等原有持久化机制保持原样。
5. 短时功能回归不能替代长时稳定性测试。
6. 构建仍提示部分资源块超过 500 kB，涉及医疗模块、图表及 Office 库。本轮未以放宽阈值消除此提示，也未做弱网冷启动性能验收；后续可用实际加载数据决定进一步拆包位置。
