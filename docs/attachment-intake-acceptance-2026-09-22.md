# 附件、患者建档与相似病例验收（2026-09-22）

交付版本：0.9.10，正式入口 `/Applications/Open Medical.app`。

## 原因与修复

此前临床会话的文件选择器、文本解析器和后端白名单均未支持图片、Word、Excel；通用项目里的图片上传是另一条路径，不能覆盖患者会话。

- 支持 PNG/JPG/JPEG/WebP、PDF、DOCX、XLSX、TXT、Markdown、CSV/TSV、JSON。图片保存原图，可预览和下载；Mac 上的文本模型通过 Apple Vision 本地 OCR 读取报告，视觉模型可直接读取图片。
- 扫描 PDF 的无文字页转换为逐页图片，保存页码并通过 OCR/视觉工具读取。混合 PDF 同时保留文本与扫描页；复制会话和确认建档时复制图片，生成目标会话自己的附件引用。
- Word 提取文本；Excel 保留工作表、行号和单元格位置，使用公式缓存结果，不执行公式、宏或外部链接。空文件明确提示“0 字节”。
- 修复材料面板假定所有解析结果都是 PDF 的错误，增加格式标签和图片预览。
- 新患者提案开放检验、就诊字段。确认建档后将本轮选中的材料与对话输入保存在患者病例会话，避免来源留在原对话。对话输入与文件分别处理，防止误认为上传文件。
- 更新建档技能：核对身份、保留疑似诊断限定词、记录来源、区分未知和无过敏、避免根据旧年龄倒推出生年份。缺少完整日期或单位的指标保留在备注，不伪造结构化数值。
- 修复实际模型生成无效 JSON 参数后，Anthropic 协议历史转换再次解析同一无效 JSON、导致运行中断的问题；失败调用保留原始参数和可修正错误，不执行错误参数。

参考了 med-agent-platform 的患者资料整理/预处理、med-agent-platform-mdt-mvp 的病历解析/资料组织，以及 find-similar-medical-cases 的指纹、主轴核验与来源分离方法。使用当前工作台实际可用工具，未照搬其他项目的 API。

## 相似病例

患者档案增加“检索相似病例 · 本地与网上”入口，填入当前患者病例会话的任务草稿。

- 本地：检索病例库与未归档患者的结构化临床信息，自动排除当前患者，避免同一患者档案和快照重复出现，不返回其他患者姓名/电话。
- 网上：增加 `online_case_search`，分别查询 PubMed、Europe PMC，记录实际来源、缓存、失败及检索式，并按 PMID/DOI 去重。
- 候选并非已核验的相似患者；技能要求核对主疾病/综合征、明确相似点/差异/未知，必要时读摘要或原文。检索分数不是诊断概率。
- 当前网上工具是上述两个来源的定向检索，并非 find-similar-medical-cases 全部中文/英文数据库的移植。

## 当前边界

- 图片单份最多 4MB；PDF/Office 输入最多 20MB；文字 PDF 最多 300 页，扫描页最多 30 页且受单次上传容量限制。
- HEIC/HEIF 目前需要先转成 JPG/PNG。图片型 Word 内嵌图片不会自动 OCR，需单独上传。
- Word、Excel、文字 PDF 保存抽取文本，未保存完整原文件；扫描 PDF 保存扫描页图而非完整 PDF 原件。需长期保留原文档时请保留外部原件。
- 本地 OCR 只识别报告文字，不能解读 CT/病理图像；模糊文字、表格顺序、数值、小数点和单位需要对照原图。
