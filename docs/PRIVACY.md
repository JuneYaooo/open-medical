# 患者资料去隐私

实现日期：2026-10-30。

目标：资料导入时就脱敏，**保存下来的就是脱敏后的资料**。

- 文字：姓名、电话、证件号、住址、联系人、出生日期、病历号替换成 `[患者姓名]`、`[电话]` 等占位符，原文不再保留。
- 图片和扫描页：按识别结果把这些位置涂黑，生成打码图并替换原图，原图删除。
- 文件名：其中出现的姓名等也会脱敏。
- 身份信息（姓名、性别、出生日期）只保存在本机 `material.privacy.identity`，用于建档时回填。

## 开关与模式

「设置 → 配置模型 → 患者资料脱敏」，接口为 `GET/PUT /api/privacy-settings`。**默认开启**，医生明确关闭后才关闭。

开启只影响之后导入的资料。脱敏会覆盖原文、删除原图，所以升级后不会自动处理已有资料；需要时在设置页点「重新脱敏未完成的资料」。

脱敏服务按以下顺序选用：

1. 设置页单独填写的服务；
2. 「文字识别」里配置的 worker；
3. 内置服务 `http://36.139.121.215:18090`。它需要 API Key：在 `model.env` 写 `MEDICAL_PRIVACY_SERVICE_KEY=…`，或在设置页只填 API Key（地址留空）。没有 Key 时不调用内置服务，只用本地规则。`MEDICAL_PRIVACY_SERVICE_URL` 可以换成自己的地址，设为 `off` 则不使用内置服务。

内置服务是公网明文 HTTP，送去脱敏的原文和 API Key 没有加密；对传输安全有要求时请自行部署 worker 并使用 HTTPS 或内网地址。

不属于患者资料的内容不脱敏：

- 从文献检索导入的 PubMed / Europe PMC 摘要；
- 助手浏览器的网页截图：规则兜底模式下可以交给视觉模型，严格模式下禁止。

| 模式 | 服务不可用或未配置时 |
|---|---|
| 规则兜底（默认） | 用本地规则脱敏后保存，资料标为 `method: "rules"`；服务恢复后可以用「重新脱敏未完成的资料」在规则结果上再过一遍服务 |
| 严格 | 先保留原文，标为 `failed`，内容不发给模型；服务恢复后重新处理 |

脱敏在导入后台进行，通常需要几秒到十几秒。这段时间内，模型看到的是本地规则的结果（严格模式下是占位说明）。

## 脱敏服务（medagent-gpu-worker）

- `POST /v1/deidentify`：规则加私有 Qwen 模型，返回前会再复检一遍。只有返回 `verified=true` 且 `policy_version` 以 `cn-medical-pii` 开头的结果才会被采用。长文本按行切成每块不超过 1500 字，最多 4 块并发处理。
- `POST /v1/identity`：抽取身份，只保存在本机。
- `POST /v1/ocr/records`：图片文字和每行坐标，用于打码。
- 默认沿用「文字识别」里配置的 worker，也可以单独配置。HTTP 和 HTTPS 都可以用；非本机的 HTTP 地址在设置页会提示原文和 API Key 是明文传输。
- 测试连接：`POST /api/privacy-settings/test`，用固定的虚构样例文本测试。

## 图片打码（`server/medical/image-redact.mjs`）

1. 开启脱敏后，原图只交给 OCR（OCR 服务的 `/v1/ocr/records`，或 macOS / Windows 系统识别），取得每行文字和坐标，不发给视觉模型。
2. 识别出的文字整体脱敏。对比原文和脱敏文本（按行做字符级最长公共子序列），原文中没对上的片段就是被替换的敏感片段。脱敏服务合并空格、吞掉相邻的字都不影响对齐，宁可多遮。
3. 在每行文字里定位这些片段：中文、全角字符按全宽算，半角字符按 0.55 倍宽算，两侧再各多遮约一个字宽。折行的片段整行遮住。
4. 用 sharp 叠加黑块，重新编码为 JPEG（丢弃 EXIF 等元数据），保存为新成果并标记 `privacy: "masked"`；替换资料引用后删除原图。需要遮却缺少坐标的行会让结果标为 `partial`，这张图不会交给视觉模型。
5. 完整打码的图片可以正常交给视觉模型（`inspect_image`、用模型重新识别）；未打码的图片只能走 OCR 加脱敏。

## 数据流

| 路径 | 开启脱敏后 |
|---|---|
| 文本资料（txt、PDF 文字层、Word、Excel） | 后台脱敏后覆盖保存；`privacy.sourceHash` 记录原文指纹，用于重复上传检测 |
| 图片、扫描页 | 识别时一并打码并脱敏文字 |
| 运行时资料、关键词检索、清单预览、子代理、语义索引 | 已脱敏的保存文本；脱敏未完成时用规则兜底或占位说明 |
| 医生界面 | 同样是脱敏后的文字和打码图 |
| OCR 修正、文字编辑后 | 文本变化，自动重新脱敏 |

## 发送前识别图片

图片只上传、不识别时，资料里只有一行索引说明。对话里 `inspect_image` 的临时识别结果不会保存，建档核对时检验值就找不到原文行。所以发送前会先识别图片并存档：

- 开启脱敏时：本轮选中的所有未识别图片和扫描页都先识别、脱敏、打码；
- 未开启时：只有对话里的建档请求（如「帮我添加这个患者」）才先识别；
- 识别进度通过事件流 `material.progress` 显示；识别会更新会话版本，但不算资料冲突；
- 识别失败的资料记下原因（`extraction.ocrFailure`），模型会看到原因，发送照常进行；同一版本不会重复识别，医生可在资料详情点「重新识别」；
- 已识别存档的图片再调用 `inspect_image` 时，会提示改用 `read_source`，不重复做 OCR，也不再调用脱敏服务；
- 建档确认时，还没识别成文字的图片会单独列为一条核对项（`source-unrecognized`），排在最前，并说明原因。

## 建档回填

模型看到的是占位符。调用 `patient_create_propose` 时，系统在本机用身份信息回填：

- 占位或泛称的姓名换成真实姓名，正文里的 `[患者姓名]` 一并替换；
- 补上缺失的性别和出生年；
- 作为占位符出现的电话、病历号字段直接丢弃；
- 多份资料的姓名不一致时不回填，并在备注里提示；已有同名患者时提示可能重复建档；
- 工具结果回给模型之前，再把回填的身份换回占位符。

## 已知边界

- 医生在对话里直接输入的姓名，以及患者档案类工具（`list_patients`、`read_patient_brief`、`read_patient_chart`）返回的姓名，仍会发给模型。
- 图片打码依赖 OCR 能读出的文字。手写体、印章、二维码、条形码、照片中的人脸不会被遮；二维码常含身份信息，需要人工留意。
- 规则兜底会漏掉没有标签的人名和地址。
- 知识库（指南、文献）的 OCR 不受影响。
