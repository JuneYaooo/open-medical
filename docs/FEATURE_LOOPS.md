# 功能闭环清单

这份清单按"触发 → 处理 → 落库 → 医生确认 → 结果回到医生视野"逐条核对现有功能。架构见 [ARCHITECTURE](ARCHITECTURE.md)。

状态：✅ 闭环；⚠️ 主链路已闭环，仍有已知缺口（见第 3 节）。

## 1. 功能地图

### 患者核心（固定区）

| 功能 | 闭环路径 | 状态 |
| --- | --- | --- |
| 患者档案 | 建档/编辑（revision 乐观锁）→ 风险重算 → 列表/简报 | ✅ |
| 材料建档 | 上传 → 抽取/OCR → 建档草稿 → 证据核对 → 确认建档 | ✅ |
| 表格导入患者 | 预览 → 提交 → 建档 → 风险重算 | ✅ |
| 检验导入 | 预览 → 逐患者 `patient-update` 提案 → 确认 → 风险重算 → 待阅检验 | ✅ |
| 提案（AI 不直写） | 工具提案 → 提出时校验 → 托盘/档案页确认或驳回 → 事务内应用 | ✅ |
| 复诊预约 | 预约 → 今日待办 → 到诊/未到诊登记（可更正） | ✅ |
| 待阅检验 | 外来新检验 → 待办 → 标记已阅；医生自己录入或在提案中核对过的检验直接记为已阅 | ✅ |
| 治疗方案复评 | 复评日期到期 → 待办 → 记录评估或改期 → 待办消失 | ✅ |
| 分组 | 规则/AI 分组提案 → 确认 → 跳过的患者（已删/已归档/满额）在托盘提示 | ✅ |
| 删除患者 | 事务内清除固定表、插件表、待确认提案、学习记录 → 删除会话 | ✅ |
| 接诊准备 | 患者总览「准备本次接诊 / 准备诊后文书」→ 读取最新速览 → 预填请求与档案快照 → 医生核对后发送 | ✅ |
| 队列查询/统计 | 结构化条件确定性遍历；结果只读，没有"批量分组/随访"后续动作 | ⚠️ |

### 风险与随访（插件）

| 功能 | 闭环路径 | 状态 |
| --- | --- | --- |
| 风险规则 `risk-rules` | 任一档案写入 → 重算；每天重算一次日期类规则（复查到期、随访逾期）→ 待办 → 知晓/处理/重开；归档患者不计入统计 | ✅ |
| 随访计划 `followup` | 计划 → 到期生成提醒 → 登记结果或推迟 → 下一次随访 | ✅ |
| 随访问卷 | 到期发出 → 回收 → 以问卷结果关闭对应提醒（一条记录）→ 评分预警 | ✅ |
| 患者消息/回复 | 消息分诊 → 红旗预警 → 回复草稿 → 发送；失败可改后重发，结果未知需人工核实后关闭 | ✅ |
| 紧急红旗 | 风险规则启用时进"风险"栏，停用时进"患者消息"栏；不会从待办消失 | ✅ |
| 专病包 `care-packs` | 安装模板/患教 → 入组提案（确认失败自动撤回）→ 随访节点 + 检验监测 | ✅ |
| 检查与转诊 `care-tasks` | 等结果 → 医生审阅 → 告知患者 → 关闭/约下次随访 | ✅ |
| 医生每日提醒 | 每日摘要（按全量计数）→ 发送回执；读取待办失败记为失败回执，不再误报"今天没有待办" | ✅ |
| 渠道网关 `channel` | 消息 → 代理会话 → 回复；渠道未连接时重试明确报错 | ✅ |
| 企业微信单聊任务 | 提交 → 自动轮询发送结果（7 天内，每 10 分钟）；结果未知的任务进工作栏，医生核实后登记"已发送/未发送" | ✅ |
| 医生分身 `feishu-knowledge-bot` | 知识库答复 → 红旗/复核 → 待办直接打开对应会话；"稍后联系"只生成一条待办 | ✅ |

### 知识与科研（固定区 + 插件）

| 功能 | 闭环路径 | 状态 |
| --- | --- | --- |
| 知识入库 | 上传 → 转写/OCR → 正文 → 分块 → 向量；失败的导入可重试或移除；重启时中断的索引自动续跑 | ✅ |
| 来源核对 | 资料状态：已核对（须填核对依据）/ 待核对 / 停用 | ✅ |
| 删除资料 | 删除库行、原文件、向量索引 | ✅ |
| 知识问答/图谱 | 混合检索 → 带行号引用 → 原文定位 | ✅ |
| 检索索引 | 知识库顶部显示嵌入模型、连接状态、仅关键词检索的资料数；可检查连接、重建全部索引 | ✅ |
| 试验入组 `trials` | 方案 → 规则预筛 → AI 初筛 → 医生核对 → 入组提案（按提案时版本防覆盖）；批量初筛在确认时先校验 | ✅ |
| 文献 `literature` | 检索 → 导入 → 证据核验（DOI 末尾标点已兼容） | ✅ |
| 学习 `learning` | 采纳/修改信号 → 候选习惯 → 确认；历史评测中断后自动清理临时草稿 | ✅ |
| 自动化规则 | 规则 → 事件求值 → 待办/草稿；修改触发条件后只对新结果生效 | ✅ |
| 后台失败 | 试验批量初筛中断、渠道断连/回复未发出、企微同步失败、每日提醒发送失败 → 今日待办「工作」栏 → 跳到处理位置 | ✅ |
| 扩展/技能 | 提案 → 确认 → 版本/回滚；AI 只能停用技能，彻底删除须医生在界面操作 | ✅ |
| 默认关闭的插件页面 | 打开已停用插件的旧链接时显示"插件未启用"，并提供设置入口 | ✅ |

## 2. 底层健壮性约定

| 约定 | 位置 |
| --- | --- |
| WebSocket 错误帧不会让进程崩溃 | `server/agent.mjs`（`ws.on("error")`） |
| 事务回滚失败不掩盖原始错误 | `server/sqlite-transaction.mjs` |
| 新版本数据库在任何迁移前被拒绝打开 | `server/store.mjs` |
| 删除工作区原子删除全部子表（归档、历史、事件、轨迹） | `server/core/workspace-store.mjs` |
| 单条损坏的工作区数据不阻断启动或定时任务 | `workspace-store.mjs` `list()` |
| 调度/恢复定时器逐工作区隔离异常 | `workspace-scheduler.mjs`、`workspace-recovery.mjs` |
| 运行锁必定释放；prepare 后启动失败用 `abandon()` 释放 | `workspace-service.mjs`、两个 scheduler |
| 不响应取消信号的工具不会拖住运行 | `tool-registry.mjs` `untilAborted` |
| 关闭流程先中断任务再停插件，每步限时，数据库最后一定关闭 | `server/agent.mjs` `shutdown` |
| 插件启停串行化，停止限时 10 秒 | `plugin-host/host.mjs` `_lifecycleCall` |
| 插件异步事件/待办来源不会产生未处理的 rejection | `plugin-host/host.mjs` |
| 单实例锁用操作系统文件锁，进程被强杀后立即释放，不靠 pid 判断 | `server/process-lock.mjs` |
| 工作区只保留每组最近一个检查点，数据量随对话线性增长；流式片段每秒最多落盘一次 | `workspace-store.mjs` `pruneStaleContexts` |
| 外发隐私过滤覆盖带材料的无患者会话；拉丁字母姓名按整词匹配 | `medical/outbound-query.mjs` |
| 可选请求体：空体视为 `{}`，损坏或超限照常报错 | `server/agent.mjs` `optionalBody` |
| 任一档案写入都会触发风险重算（事务结束后执行） | `server/patients.mjs` `markChanged` |

回归测试：`tests/core/robustness.test.mjs`。

## 3. 已知缺口

首轮清单中的 10 项缺口已处理。下面是设计取舍和尚未处理的小问题。

设计取舍：

1. **知识整理、试验初筛重启后不自动续跑**：两者都会把资料发给大模型，需要医生每次授权。试验批量初筛中断会进今日待办工作栏；知识整理中断显示在知识库页，可重试或移除。
2. **嵌入服务配置**仍通过环境变量（`MEDICAL_EMBEDDING_KEY` 等）；界面只提供状态、连接检查和重建索引。
3. **旧接口 `POST /api/reminders/:id/ack`** 为兼容保留，可不登记结果关闭提醒；现在会在记录上标明并写审计。

尚未处理的小问题：

- 部分插件提案（`followup.plan.*`、`care-packs.apply`、`care-settings`）在托盘里显示为原始 JSON，没有专门的预览。
- `followup-create` 提案绑定档案版本，档案任何无关修改都会让它失效。
- 切换飞书应用后，旧应用会话中未处理的红旗不再显示。
- 确认 `patient-create` 时，材料文件在数据库事务内复制；事务回滚会在磁盘上留下文件。
- 习惯"已采用"在生成草稿时计数，而不是医生确认时。
- 自动化规则执行失败后不会重试（失败已记录并可见）。
- 相似病例结果没有"有用/存入病例库"反馈；队列查询结果没有批量分组/随访的后续动作。
- 智能体的 `appointment_update` 工具不能更正已登记的到诊结果。
- 问卷 AI 解析接口没有界面入口。
- 多重比较计数每次运行重置。
