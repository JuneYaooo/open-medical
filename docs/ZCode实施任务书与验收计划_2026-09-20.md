## 第一批：可启动、可执行的通用工作区

### A. 修复授权写入范围的跨平台判断

问题：Windows path.relative 返回反斜杠，部分授权比较使用正斜杠，导致范围内子文件被错误拒绝。检查 WorkspaceService.assertWriteScope、AgentTeam 及已有 write-scope 工具，统一路径边界语义。

验收：授权 docs 后 docs/a.md、嵌套目录、中文和空格路径可以写入；docs-other、上级穿越、绝对路径越界仍被拒绝；符号链接不能绕过边界。Windows 与 POSIX 的路径语义均有覆盖；缺少创建符号链接权限必须明确跳过，不能降低安全约束来通过测试。

### B. 通用后端拥有可独立使用的前端

问题：独立 WorkspaceServer 仍提供医疗前端，启动时请求不存在的 /api/sessions，显示“接口不存在”；通用工作区未形成完整产品入口。

实现要求：明确服务模式和能力契约；通用模式使用工作区/任务接口，支持创建、打开、发送任务、流式结果、停止、重载恢复和产物查看。医疗模式复用通用交互，不能通过伪造医疗接口或隐藏报错掩盖不兼容。

验收：只启动通用服务即可完成上述操作；浏览器无错误的医疗接口请求；通用首页不要求创建患者；医疗入口原有基本路径仍可用。模型未配置时给出准确配置引导，不能显示成功回答。提供两种服务模式的浏览器验证记录。

顺序：先 A，再 B，每项独立审查。第一批不扩大到自主多代理、长期记忆或患者管理新功能。

## 第二批：可信的任务执行闭环

1. 定义任务状态与交付依据：对话回答、工具执行、产物交付分别处理；涉及文件或执行的任务必须能够核对实际结果，不能只凭模型自然语言判断已完成。
2. 梳理取消、失败重试、进程重启恢复、工具超时、幂等和重复副作用；建立稳定事件契约，确保 UI 与后端状态一致。
3. 按当前环境与授权展示可用工具。缺失 Docker、模型、浏览器或连接器时明确说明受限能力；不得静默切换到未授权宿主执行。
4. 通用项目移除无关医疗提示与工具，医疗能力按场景启用；先测量提示长度、工具选择错误和成功率变化，再判断收益。

验收必须包含：模型声称文件已生成但文件不存在；工具失败后继续执行；中途取消；重启恢复；重复确认；缺少依赖。普通问答仍能直接回答，不强制每轮调用工具。

## 第三批：真实模型与体验基准

使用项目桌面端已保存的模型配置，不导出或显示密钥；先确认保存配置的机器。固定代码版本、模型、任务材料、权限和环境，每项至少重复三次。比较框架能力时尽量固定模型；无法固定时明确模型差异。

基准至少覆盖：文件整理、跨文件检索、网页资料与引用、结构化表格、文档产物、多步骤修改、工具故障恢复、用户中途纠正、取消、重启续作。使用合成或公开材料。

记录最终产物是否正确、是否需人工救援、工具错误、首个有效反馈时间、完成时间、操作次数和可获得的 token/费用。产品验收看真实任务与产物，不用测试数量或工具数量代替。

建议进入医疗化前的门槛：固定基础任务集重复运行成功率至少 90%；越权写入和无产物却报告交付的验收案例全部通过；停止与恢复案例全部通过；通用任务不需要患者对象；失败原因和下一步可被普通用户理解。上述是拟定目标，当前未证明达到。

## 第四批：医疗领域接入

通用底座通过验收后，把患者上下文、随访、待确认建议、临床记录与审计作为领域能力接入。已有患者数据丢失、旧建议覆盖新编辑、数据外发边界问题需要独立优先修复，不因延期医疗新功能而延期数据完整性修复。
