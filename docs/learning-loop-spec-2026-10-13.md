## 0. 背景与目标

### 0.1 宣传承诺 vs 现状

| 宣传片承诺 | 现状（代码依据） | 本规格是否覆盖 |
|---|---|---|
| 上传 → 提取 → 你核对一遍 → 建档 | 草稿只读，只能写自由文本让模型重跑（`src/patient-intake.jsx:240-256`）；确认接口不收内容（`server/agent.mjs:1583`） | ✅ P0 |
| 你确认过的写法和习惯，它会记下来 | 明确说出的偏好也只生成待确认候选；修改不被记录；同一字面信号重复 2 次才成候选（`server/medical/doctor-profile.mjs:326`） | ✅ P2（说过即记，不再确认） |
| 下一次整理病历，它带着你的知识、案例、习惯一起来 | 建档仅注入 ≤800 字偏好摘要（`medical-workspace-domain.mjs:135`）；知识库/相似病例工具被建档白名单剔除（`intake-tools.mjs:6`） | ✅ P1 |
| 再遇到相似的患者，翻出你自己的经验 | 仅手动"看看相似患者"/对话正则触发 | ✅ P1 |
| 用得越久，积累越厚，它就越顺手 | 无任何度量 | ✅ P0 指标 + P3 |

### 0.2 一句话目标

让 **"医生修改 → 被记录 → 被提炼 → 下次被带上 → 改得更少"** 这个飞轮在建档场景转起来，并且**看得见、可撤销、可证明**。

### 0.3 北极星指标

**草稿改动率** = 医生在确认前对 AI 草稿做的条目级改动数（改 + 删 + 增）÷ AI 草稿条目总数。

- 统计口径：仅建档草稿（P0），后续扩展到病历文书（P2b）。
- 目标：同一医生连续使用 30 份建档后，改动率较前 10 份下降 ≥ 30%。
- 辅助指标：核对用时（打开草稿 → 确认）、"按补充内容重新整理"次数、习惯被改回率。

### 0.4 非目标

- 不从修改里学习**医学结论**（诊断状态、用药决策、剂量）。这类改动只记录、只统计，不自动变成习惯。
- 不做跨医生/跨机构的共享学习（全部本机）。
- 不做模型微调；只做上下文层面的个性化（习惯 + 范例 + 知识注入）。

## 2. P0：可编辑核对 + 差异记录 + 度量（地基）

### 2.1 交互：核对建档草稿（改造 `PatientIntakeModal` 的草稿区）

#### 2.1.1 布局

```
核对建档草稿                                   [已改 3 处 · 全部还原]
───────────────────────────────────────────────────────────────
张三 · 男 · 1968 年生 · 138****                         [编辑]
病史摘要                                                [编辑]
  ……（只读展示，点编辑变文本框）
  来源：门诊记录 2026-09-01 第 3-12 行

诊断与问题 (4)                                         [+ 添加]
  ● 2 型糖尿病 · 确诊 · 来源：…                    [改] [删]
  ● 高血压 · 确诊                         已改 ↺       [改] [删]
  ● 肝囊肿 · 影像发现                     已删除 ↺            （删除线）
  ● 高脂血症 · 疑似待排                   你添加的 ×
用药 (3) ……
检验 (12) ……  [展开全部]
就诊经历 (2) ……
过敏史：待核对 ▾

本次参考了：2 条你的习惯 · 1 份你的历史档案 · 1 篇指南   ▸   （P1 起出现）
───────────────────────────────────────────────────────────────
需要补充或纠正？直接告诉我 [……………………]  [按补充内容重新整理]
                                                     [确认建档]
```

#### 2.1.2 条目编辑规则

| 动作 | 交互 | 结果标记 |
|---|---|---|
| 改 | 点 [改] → 该行原地展开为表单（字段见 2.1.3），[保存]/[取消]；Esc 取消，Enter（非文本域）保存 | 行尾显示 `已改 ↺`，悬停显示"AI 原文：……" |
| 删 | 点 [删] → 行变删除线 + 灰色，不立即消失；同时出现一行轻量原因选择（可跳过）：`资料里没有` `重复` `不该算诊断` `不重要` `其他` | `已删除 ↺` |
| 添加 | 点分区标题旁 [+ 添加] → 在分区末尾插入空表单 | `你添加的 ×`（× 直接移除） |
| 还原单条 | 点 `↺` | 恢复 AI 原文，去掉标记 |
| 全部还原 | 顶部 `全部还原`，二次确认"放弃你做的 N 处修改？" | 回到 AI 草稿 |

- 删除原因**可选**，不弹窗、不阻塞；选了会作为差异的 `reason` 存下（P2 用来区分"提取错了"与"不需要"）。
- 编辑表单内校验与现有 `patients.create` 规则一致（日期格式、诊断 status 枚举等）；不合法时字段下方红字，保存按钮不可用。
- 身份字段（姓名、性别、出生年、电话）可改，但**不进入学习**（见 2.3 `learnable=false`）。

#### 2.1.3 各分区编辑字段

| 分区 | 字段 |
|---|---|
| 诊断 | name, status（确诊/疑似待排/影像检验发现/待核对）, date, note |
| 用药 | name, dose, frequency, status（正在使用/已停用/待核对）, note |
| 检验 | date, item, value, unit, note |
| 就诊经历 | date, reason, note |
| 病史摘要 | 多行文本 |
| 过敏史 | allergyStatus 下拉 + 过敏原列表 |
| 分组 / 标签 | chips 增删 |

`sources` 字段不可编辑；医生新增的条目 `sources=[]`，展示"医生补充"。

#### 2.1.4 自动保存与恢复

- 每次条目保存/删除/还原后 600ms 防抖，`PATCH /api/pending-actions/:id/review-draft` 保存当前编辑版。
- 关闭弹窗、刷新、从"建档任务"列表回来时，草稿区展示**编辑版**，顶部提示"已恢复你上次的 N 处修改"。
- 保存失败：顶部黄条"修改暂未保存到本机，请勿关闭窗口"+ 自动重试 3 次。

#### 2.1.5 与"按补充内容重新整理"的冲突处理

当已有手动修改（N>0）时点 [按补充内容重新整理]：

```
重新整理会生成一份新草稿。你手动做的 3 处修改怎么处理？
  ( ) 告诉 AI 我改了什么，让它在新草稿里保留   ← 默认
  ( ) 丢弃我的修改
                                    [取消] [继续]
```

- 选"保留"：把差异摘要（"诊断「HTN」改为「高血压」；删除「肝囊肿」，原因：不该算诊断；新增用药「阿托伐他汀 20mg qn」"）拼到 `correction` 前部发给模型。新草稿出来后，**重新以新草稿为 AI 基线**计算差异（旧差异作为 `superseded` 留档，不计入改动率，但计入学习信号——因为那是医生真实表达过的修改）。
- 选"丢弃"：旧编辑版清除，旧差异同样以 `superseded` 留档。

#### 2.1.6 确认

- [确认建档] 文案随状态变化：无修改"确认建档"；有修改"确认建档（含你的 3 处修改）"。
- 请求：`POST /api/pending-actions/:id/confirm`，body `{ payload: <编辑版>, reviewMs: <核对用时> }`。
- 确认成功后进入患者档案（现有 `onCreated`），P2 起如有新习惯生效，会显示一行"记下了"通知（见 4.3）。

### 2.2 接口

| 接口 | 说明 |
|---|---|
| `PATCH /api/pending-actions/:id/review-draft` | body `{ payload }`；仅 `patient-create` 且 `status=pending`；服务端用与 create 相同的 normalize 校验；存到 action 的 `reviewDraft` 字段（不覆盖原 `payload`） |
| `POST /api/pending-actions/:id/confirm` | 新增可选 `payload`、`reviewMs`。有 `payload` 时：校验 → 以其建档 → 写 ReviewLog（AI 基线 = 原 `payload`）。无 `payload` 时行为不变，ReviewLog 记为"零修改" |
| `GET /api/review-stats?range=90d` | 返回改动率时间序列、按分区拆分、核对用时中位数 |

`pending-actions.mjs` 的 `confirm()` 中 `patient-create` 分支：`this.patients.create(feedback.payload ?? action.payload)`，并在同一事务内 `reviewLog.record(...)`。其它 action 类型忽略 `payload`（防止借此绕过校验）。

### 2.3 数据模型（SQLite，本机）

```sql
CREATE TABLE review_sessions (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,             -- 'intake' | 'artifact'(P2b) | 'chart_edit'(P2b)
  action_id TEXT, patient_id TEXT,
  model TEXT,                     -- 生成草稿的模型
  context TEXT,                   -- P1：本次注入的 {habitIds, exampleIds, kbRefs, skillIds}
  ai_items INTEGER, modified INTEGER, added INTEGER, deleted INTEGER,
  review_ms INTEGER,
  ai_snapshot TEXT, final_snapshot TEXT,   -- JSON；身份字段在快照中脱敏存储
  created_at TEXT
);
CREATE TABLE review_diffs (
  id INTEGER PRIMARY KEY,
  session_id TEXT NOT NULL,
  section TEXT,                   -- diagnoses|medications|labs|visits|clinicalSummary|identity|allergy|tags
  op TEXT,                        -- modify|add|delete
  field TEXT,                     -- 改了哪个字段，如 'name' 'unit' 'status'
  before TEXT, after TEXT,        -- 条目 JSON 或字段值
  reason TEXT,                    -- 删除原因（可空）
  category TEXT,                  -- P2 分类结果：term|format|unit|clinical|omission|spurious|style|identity
  learnable INTEGER,              -- identity/clinical 为 0
  superseded INTEGER DEFAULT 0,
  habit_id INTEGER,               -- P3：若该修改是"改回某条习惯的自动修正"
  created_at TEXT
);
```

### 2.4 差异计算（`shared/review-diff.mjs`）

1. 列表分区按**键**对齐：诊断 = 规范化 name；用药 = 通用名；检验 = item+date；就诊 = date+reason 前 10 字。
2. 键对不上的，再按相似度（字符 bigram Jaccard ≥ 0.6）配对，视为 modify。
3. 仍未配对：AI 侧 → delete，医生侧 → add。
4. modify 拆到字段粒度，一个条目改了 name 和 unit 记两条 diff（便于后续分类）。
5. 病史摘要：整段一条 diff，附 `charDelta`、`lengthRatio`（P2 风格学习用）。

前端用同一函数实时标"已改"，保证用户看到的标记与入库差异一致。

### 2.5 度量展示：医生画像页新增「它学得怎么样」

位置：`src/doctor-profile.jsx`，在"当前注入摘要预览"之上。

```
它学得怎么样
  最近 30 份建档，你平均每份改 2.1 处（之前 30 份：4.6 处）  ↓54%
  [折线：每周平均改动率]  按分区 ▾
  改得最多的地方：检验单位（38%） · 诊断名称（22%） · 病史摘要（20%）
  核对用时中位数：1 分 40 秒
```

- 少于 5 份确认：只显示"再确认 N 份建档后，这里会显示 AI 草稿的改动趋势"。
- "改得最多的地方"可点击，跳到该分区最近 10 条修改明细（只读，患者名打码）。

### 2.6 P0 验收

- [ ] 草稿每个分区都能改/删/加/单条还原/全部还原，刷新后修改仍在。
- [ ] 有修改时确认，档案内容 = 编辑版；`review_sessions/diffs` 落库且计数正确。
- [ ] 重新整理冲突对话框两条路径都正确，`superseded` 标记正确。
- [ ] 无修改确认与旧行为一致（回归 `tests/` 现有建档用例）。
- [ ] 画像页"它学得怎么样"在 <5 / ≥5 份时显示正确。

## 3. P1：下次整理时带上「你的知识、案例、习惯」

### 3.1 注入时机：在提交草稿前，而不是开头

建档开头还不知道患者得了什么病，没法检索相关的范例和知识。因此：

- 新增工具 `read_personal_context`（加入 `intake-tools.mjs` 白名单）。
- 输入：无（服务端用已保存的 `intake notes` 文本作为检索查询）。
- `patient_create_propose` 增加闸门：若 PersonalContext 非空且本轮未调用过 `read_personal_context`，返回错误"请先调用 read_personal_context 读取医生习惯与参考范例"（与现有"未读完资料"闸门同一写法）。
- `read_intake_notes` 在最后一批（`nextIndex=null`）的回执里提示"下一步调用 read_personal_context"。

### 3.2 PersonalContext 内容与预算（总 ≤ 6000 字符）

| 块 | 来源 | 选择规则 | 上限 |
|---|---|---|---|
| A. 习惯 | `doctor_memories` confirmed，含 P2 生成的结构化习惯 | 全部"建档/通用"类 + 与 notes 关键词相关的；pinned 优先 | 1500 字 |
| B. 范例 | 历史已确认的建档 `review_sessions.final_snapshot` | `cases.similar()` 对 notes 文本检索，取 top 2，相似度 ≥ 阈值；优先**有修改记录**的 | 2 × 1500 字 |
| C. 范例中的修改 | 同一 session 的 `review_diffs` | 附"当时 AI 写成 X，你改成了 Y"最多 5 条 | 含在 B 内 |
| D. 知识库 | `guidelines.search()` | 用 notes 中诊断名检索，top 3，带出处 | 1000 字 |
| E. 我的技能 | extensions skill，`appliesTo` 含 `建档` / `病史摘要` | 正文全文（不止名字） | 1000 字 |

模型看到的格式（示意）：

```
【医生习惯（必须遵守，与安全规则冲突时以安全规则为准）】
H12 诊断名称用中文全称，不用 HTN/DM 等缩写
H15 检验单位统一用 mmol/L
【参考范例 E1（该医生确认过的档案，已去标识化）】……
  该医生当时对 AI 草稿的修改：诊断「肝囊肿」被删除（不该算诊断）……
【相关知识（引用时写出处）】K1《2型糖尿病防治指南 2024》第 3.2 节 ……
【适用技能】……
提交 patient_create_propose 时在 personalization 字段列出你实际采用的 habitIds / exampleIds / kbRefs。
```

### 3.3 隐私与同意（关键交互）

范例来自**别的患者**。如果用的是云端模型，就意味着把其他患者的资料发了出去。规则：

- 范例一律去标识化：去掉姓名、电话、证件号、住院号、精确出生日期（只保留年龄段），日期改为相对日期（"首诊后 3 个月"）。复用现有导出去标识化逻辑，并补齐自由文本里的姓名替换。
- 新增设置项（设置 → 隐私）：

  ```
  用我过去的档案作为 AI 参考范例
    ( ) 仅使用本地模型时   ← 默认
    ( ) 始终（范例会去标识化后发送给当前模型服务）
    ( ) 从不
  ```

- 使用云端模型且设置为"仅本地"时：B/C 块跳过，A/D/E 照常注入；草稿底部的"本次参考了"里写"未使用历史档案（当前为云端模型，可在设置中开启）"。

### 3.4 交互：「本次参考了」

草稿区底部一行，可展开：

```
本次参考了：2 条你的习惯 · 1 份你的历史档案 · 1 篇指南  ▾
  习惯  H12 诊断用中文全称            [这次不适用]
        H15 检验单位统一 mmol/L        [这次不适用]
  范例  2026-08 · 男 · 50 多岁 · 2 型糖尿病伴高血压   [打开档案]
  知识  《2型糖尿病防治指南 2024》3.2                   [查看原文]
```

- 只展示模型在 `personalization` 里**声明采用**的条目，未采用的不展示。
- 条目级标注：被某条习惯影响的条目行尾显示小标签 `按习惯 H12`，悬停显示习惯原文。
- [这次不适用]：只记一个负信号（`habit_feedback`，P3 用），不改草稿。

### 3.5 相似病例自动卡片

确认建档后进入患者档案，若 `cases.similar()` 有 ≥ 1 条高于阈值的结果（来源可以是案例库，也可以是历史患者）：

```
你过去的相似病例（3）                                    [收起] [不再提示]
  · 李某 · 2025-11 · 2 型糖尿病伴肾病 3 期 · 你的案例笔记："……"   [打开]
  · ……
```

- 位置：患者档案页概览顶部，紧挨"新检验结果"横幅下面。
- 纯本地计算，不调用模型，不需要同意。
- "不再提示"作用于全局（写进 workbench_prefs）；"收起"只作用于当前患者。
- 打开卡片、点 [打开]、点 [不再提示] 都记录事件，用来调相似度阈值。

### 3.6 P1 验收

- [ ] 建档流程未调用 `read_personal_context` 时，提交草稿会被闸门拦下。
- [ ] 各块预算生效；没有可用内容时工具返回空，闸门放行。
- [ ] 云端模型 +"仅本地"设置下，请求里查不到任何其他患者的文本（加测试断言）。
- [ ] "本次参考了"只展示模型声明采用的条目；`按习惯` 标签可以对回具体条目。
- [ ] 相似病例卡片三种关闭方式都正确。
- [ ] 离线对比：固定 10 份测试资料，有/无 PersonalContext 的改动率（用已有确认版作为金标准）。

## 4. P2：从修改里学

### 4.1 差异分类（`HabitLearner.classify`，确定性规则优先）

| category | 判定 | learnable | 能形成的习惯类型 |
|---|---|---|---|
| `term` | 同一条目的 name 被替换，前后是缩写/同义（内置词表 + 编辑距离） | ✅ | `term_replace {section, from, to}` |
| `unit` | value 数值不变，unit 变了 | ✅ | `unit_normalize {item, from, to}` |
| `format` | 日期格式、剂量写法（"bid"↔"每日两次"） | ✅ | `format_rule {field, pattern}` |
| `spurious` | 删除，原因为"不该算诊断/不重要"，或同类条目反复被删 | ✅ | `exclude_rule {section, matcher}` |
| `omission` | 医生新增，且原文资料里有对应内容（search_materials 能命中） | ✅ | `attend_rule {section, hint}`（提醒模型注意提取） |
| `style` | 病史摘要的修改 | ✅（聚合后由模型归纳） | 自由文本习惯 |
| `clinical` | 诊断 status、用药 status、剂量数值、检验数值的修改 | ❌ 只统计 | — |
| `identity` | 身份字段 | ❌ | — |

`clinical` 的改动说明 AI 读错了或判断有误，会进"提取错误统计"给产品侧看，但**绝不**变成"以后都这样判断"的习惯。

### 4.2 原则：说过的直接记，不反复确认

医生的明确表达本身就是确认。学习结果**直接生效**，事后告知、随时可撤销，不弹"要记住吗"。

| 来源 | 例子 | 处理 |
|---|---|---|
| ① 明确说出 | 对话里"以后诊断都写全称"；"补充或纠正"框里"单位统一 mmol/L"；删除原因选"不该算诊断" | **当场生效**，写入 `doctor_memories(status='confirmed', origin='stated')` |
| ② 从修改里归纳 | 没说过，但反复把 HTN 改成高血压 | 达到阈值且试跑通过后**自动生效**，`origin='learned'` |

两种来源都只是事后发一条通知（4.3），医生不需要做任何操作。

改动点：`doctor_memory_propose` 不再生成 pending 候选，改为直接写 confirmed（工具改名为 `doctor_memory_save`）；现有画像页"待确认"标签只保留给 style 类归纳失败、需要医生补一句话的少数情况。

### 4.2.1 明确说出的识别

- 对话：沿用系统提示里的"医生陈述偏好时记录"规则（`medical-workspace-domain.mjs:26,30`），工具改为直接保存。
- 建档"补充或纠正"框：重新整理前，先用一次轻量抽取，把其中**面向以后**的表述（含"以后/都/一律/统一/我习惯"）存为习惯；只针对本患者的（"第二份报告是术前检查"）不存。
- 删除原因：选"不该算诊断/不重要"时，同类条目（相同 matcher）再出现 1 次即生效，不必等 3 次。
- 范围：医生自己明确说出的用药、检查习惯（如"二甲双胍我一般从 500mg 起"）**也直接记**，因为这是医生本人的决定，与现有画像"常用药物与剂量习惯"一致；只是从修改中**推断**临床判断这件事不做（见 4.1）。

### 4.2.2 从修改里归纳：聚合规则

- 模式键：`category + section + 归一化(from→to | matcher)`。
- 触发条件：同一模式 **≥ 3 次，且来自 ≥ 2 位患者**（排除单个患者资料的特殊情况）。
- `style` 类：累计 ≥ 5 次摘要修改后自动归纳。本地模型直接运行；云端模型只发送去标识化的修改片段，归入"使用当前模型处理资料"的已有同意范围，不另外询问。
- `doctor_memories` 新增列：
  - `origin TEXT`：stated | learned；
  - `rule TEXT`：结构化规则 JSON，可空；
  - `evidence TEXT`：最多 5 条 diff id 或原话；
  - `dryrun TEXT`：试跑结果。
- 替换现有的"同一字面信号重复 2 次 → pending"逻辑。

### 4.3 交互：「它记下了」通知（不打断、不提问）

**时机**：习惯生效的那一刻。明确说出的，在对话或建档弹窗里当场显示；从修改归纳的，在医生确认建档、进入档案页后显示。

```
✓ 记下了：诊断写中文全称，不用缩写（你改过 3 次）     撤销 · 查看
```

- 一行轻提示，5 秒后自动收起，不需要点任何按钮。
- 同时生效多条时合并成一行："记下了 2 条习惯 · 查看"。
- [撤销] → 习惯删除，该模式键加入抑制表，之后不再从修改中归纳同一条；如果医生以后又明确说出，仍然照记。
- [查看] → 跳到画像页「记忆」，定位到该条，可编辑措辞。
- 对话里明确说出的，助手回复里直接带一句"已记下，以后整理时都会这样写"，不另弹提示。
- 漏看了也没关系：草稿里受影响的条目都带 `按习惯 Hxx` 标签，画像页有完整列表。

### 4.4 试跑：自动生效前的把关（替代人工确认）

既然不再询问医生，"会不会改错"就由试跑来把关：

- 确定性规则（term / unit / format / exclude）：在最近 N（≤ 30）份 `ai_snapshot` 上应用，统计：
  - **会改对**：应用后与 final_snapshot 一致；
  - **会改错**：原本 AI 写对了，应用后反而与 final 不一致；
  - **无关**。
- 生效条件：会改对 ≥ 2 且 会改错 = 0。
- 有会改错时：自动收窄规则范围后重试一次（例如只作用于 diagnoses 分区，或限定某个检验项目）；仍不满足就保持"观察中"继续积累，**不打扰医生**。
- `style` / `attend` 类无法确定性试跑：直接生效，但只进 PersonalContext，不做后处理改写。
- 明确说出的习惯**不经过试跑**：医生说了就记。但如果试跑发现它会和医生之后的实际修改冲突，账本会记录下来（见 5.3）。

### 4.5 生效方式

| 习惯类型 | 生效方式 |
|---|---|
| term / unit / format / exclude | ① 写进 PersonalContext A 块告诉模型；② **同时**在模型出草稿后做确定性后处理兜底。被后处理改动的条目带 `按习惯 Hxx` 标签，单条可还原 |
| attend / style / 自由文本 | 只写进 PersonalContext A 块 |

后处理在服务端 `patient_create_propose` 落库前执行，同时保留"后处理前"的版本。差异计算的 AI 基线 = **后处理后**的版本（医生看到的就是基线），并另外记录哪些条目是后处理改的（P3 统计被改回用）。

### 4.6 P2b：扩展到病历文书和档案编辑

- 文书产物：`session-bridge.mjs` 已经保留了 `a.history`，在文书保存时用 `review-diff` 的文本模式（段落级）算差异，写入 `review_sessions(kind='artifact')`。替换 `extensions.recordEdit` 只计数的做法；`evolve()` 的"建议建专属技能"附上真实的修改样例（`before→after` 片段），不再需要医生在对话里从头讲。
- 档案编辑（`patients.update`）：只记录、只统计，`learnable=0`。档案编辑大多是临床更新，不是纠正写法。

### 4.7 P2 验收

- [ ] 分类器单测：每个 category ≥ 5 条正例 + 3 条反例；clinical 一律不可学习。
- [ ] 对话、补充框、删除原因三个入口明确说出的习惯，当场生效并显示"记下了"，无任何确认步骤。
- [ ] 补充框里只针对本患者的话不会被存成习惯。
- [ ] 阈值（3 次 / 2 位患者）和抑制表生效；撤销后同一模式不再自动归纳。
- [ ] 试跑数字与手工核对一致；会改错 > 0 时不生效，收窄重试逻辑正确。
- [ ] 后处理标签可单条还原；还原会记成"被改回"。

## 5. P3：生效追踪与自动退场

### 5.1 每条习惯的账本

`habit_stats`（视图或表）：applied（被后处理或模型声明采用的次数）、reverted（被医生改回）、notApplicable（点了"这次不适用"）、该分区改动率在启用前后 30 天的对比。

### 5.2 画像页「记忆」卡片增加

```
H12 诊断名称用中文全称，不用缩写            来自 3 次修改 · 2026-10-02 记住
  生效以来：用上 18 次 · 被你改回 1 次 · 诊断名称改动率 31% → 9%
  [编辑] [停用] [删除] [查看来源修改]
```

### 5.3 自动退场

- **从修改归纳的习惯**（learned）：被改回率 ≥ 30%（且 applied ≥ 5），或"这次不适用" ≥ 3 次 → **自动暂停**，并显示一行通知："暂停了习惯「H12」：最近常被你改回 · 恢复"。理由与生效相同：学错了就自己退，不让医生来回处理。
- **明确说出的习惯**（stated）：不自动暂停，因为那是医生的原话。同样条件下改为在画像页该条目上标"最近常被改回，可能已不适用"，医生自己决定是否修改。
- 如果医生之后的明确表述与旧习惯冲突（"现在缩写也可以"），新话覆盖旧习惯，旧版本留在历史里，不询问。
- 习惯从不自动删除，暂停或删除后都可以恢复（沿用扩展中心的版本/回滚思路）。

### 5.4 个人回归评测（可选，医生主动触发）

设置 → 模型 →「用我的历史档案测一下这个模型」：在去标识化的最近 10 份资料上重跑建档（需同意；本地模型无需），与确认版比较，输出改动率。用于换模型或升级提示词前后做对比。`evals/` 下同时新增一套项目自带的建档金标准集（用 `examples/` 的虚构资料），在 CI 里跑同样的指标。

## 7. 不可突破的边界

1. 红旗预警、引用出处要求、发给患者前的确认、知情同意：永远不进入学习，也不受习惯影响。PersonalContext 的头部固定写"与安全规则冲突时以安全规则为准"。
2. `clinical` 类改动永远不形成习惯。
3. 写法类习惯不需要医生确认：明确说出的当场生效，从修改归纳的经试跑把关后自动生效；两者都有通知、撤销和完整历史。从修改中推断临床判断这件事始终不做。
4. 范例去标识化，跨患者内容默认不发往云端模型。
5. 所有学习数据只在本机 SQLite。"导出我的习惯"只导出习惯规则，不导出差异原文。
6. 一键清空：画像页 → 记忆 →「清空学习记录」，清空 review_* 和 consolidated 记忆，二次确认。
