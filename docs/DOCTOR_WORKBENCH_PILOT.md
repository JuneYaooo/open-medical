# 下一步：用真实医生工作验证是否值得每天打开

这是后续试点方案，不是已完成的医生研究或承诺的临床效果。首批暂选需要长期跟踪患者的门诊医生；专科尚待确认。

## 要验证的产品判断

医生最先感受到的价值应是：**今天不会漏掉该处理的人；打开患者就能接上上次工作；新资料和后续安排不用重复整理。**

公开资料给出方向，不能代替本地用户证据。国家卫健委 2025 年实施意见将基层辅助诊疗、随访管理和连续服务列入应用方向；它并不证明本产品有效。[官方文件](https://www.nhc.gov.cn/guihuaxxs/c100133/202511/d1a42ae835c743b9b3e83ac0253c3e9f.shtml)

ONC 对实施健康信息技术的说明强调让实际使用的临床人员参与、把登记和患者检索过程设计清楚，以减少重复档案和患者混淆。因此本轮先做同名核对、编号、当前患者绑定和完整操作链路。[实施说明](https://healthit.gov/clinical-quality-and-safety/safer-guides/implementing-health-it/)

## 一次 30–45 分钟的观察

先让医生用自己原来的方式描述和演示最近一次真实工作中的步骤，再给合成患者材料。不要先演示产品，不用“你喜欢这个功能吗”代替观察。

| 给医生的任务 | 观察什么 | 产品当前支持 |
| --- | --- | --- |
| “你开始门诊前会先处理什么？” | 是否理解首页队列，能否说出下一步；是否需要别的排序 | 分类待办与来源直达 |
| “名单里有同名患者，请找到这一位并补上资料。” | 是否发现编号、是否误建/误选；首次导入是否省事 | 预览导入、编号冲突、同名确认、搜索 |
| “这位患者上次联系过，这次带了新报告，请准备接诊。” | 查阅多少页面、是否重复录入；能否找到停用药与未知过敏史 | 诊前速览、联系历史、资料来源 |
| “模型提取了一条新检验，请确认它有没有改掉既往记录。” | 是否能理解前后差异；误采纳、漏删改风险 | 默认追加、前后对照、版本冲突阻止 |
| “检查结果已收到，还没告知患者，请处理到下一步。” | 是否把收到结果误认为结束；是否找到告知和下次安排 | 结果、核对、告知、随访分阶段 |
| “这份指南版本变了，请找到旧依据并记录复核情况。” | 是否找到原文和版本；是否知道停用资料的检索表现 | 来源、版本、复核、停用、行号原文 |

最后再问三件事：哪个步骤比原来省事；哪一步会阻止你明天继续用；只能留下一个入口时选哪一个。记录原话和具体场景，不只记录满意度。

## 记录与判断

每项任务记录：是否独立完成、用时、错误/返工次数、求助点、需要重复输入的字段、最后是否能找到保存的记录。模型场景另记生成等待和医生修改时间；不能把模型响应快等同于医生省时。

可以预先约定以下**产品试点目标**，它们不是临床标准：

- 5 位医生中至少 4 位无需演示就能从首页找到明确下一步。
- 建档、找患者、登记联系、跟进报告这些确定性任务，在两次练习后不需要旁人指导。
- 同名和提案复核任务中不允许出现未被发现的患者误选；一旦出现先修流程，再继续试点。
- 相比各自原流程，至少一个高频场景减少重复填写或总完成时间；不预设统一“节省百分比”。
- 一周后根据实际打开和完成记录判断是否愿意持续使用；单次试用的口头称赞不作为留存证据。

小样本用于发现问题，不用于估计总体临床安全性或疗效。试点内容与数据范围需按合作方真实流程另行确定；本轮没有开展这一步。

## 根据发现决定下一轮

| 如果观察到 | 下一步优先做 | 暂缓的扩张 |
| --- | --- | --- |
| 主要时间花在把纸质/图片报告录入 | 本地扫描件 OCR 与逐项核对，保留原页定位 | 新增更多空泛场景卡片 |
| 医生诊后大量重复写同样的文书 | 由医生确认的专科模板和常用片段，版本可追踪 | 没有样例支撑的大量自动模板 |
| 信息已在医院系统，重复搬运最痛 | 优先研究该机构允许的导入或接口，做单条真实联通链路 | 一次性覆盖所有 HIS/EMR |
| 一个医生跟踪不完，需要团队交接 | 责任人、交接状态、机构权限和审计 | 直接把单机共享数据库当多人系统 |
| 待办太多，看了也不知道先做谁 | 基于可解释字段的排序与医生可调整的规则 | 未经验证的自动临床优先级打分 |
| 知识检索命中但医生不信 | 更好的来源定位、适用范围、更新时间和反馈闭环 | 仅追求检索条数或更长回答 |

通用 Agent 底座独立验收：真实模型、工具失败恢复、来源读取、长任务、交付验证和权限不能因医疗入口简化而弱化。试点中的医疗体验反馈与底座可靠性问题分别记录，避免把模型能力不足掩盖成界面问题。
