# 医生端患者管理（0.3）

患者管理是 0.3 新增的主视图，目标是把"病例导入 → 自动整理 → 分组 → 治疗评估草稿 → 随访计划 → 定时提醒 → 私域消息归档"做成一个本地闭环。架构原则：**每位患者关联一个既有会话作为病例工作区**，材料导入、医疗工具、产物复核、持久调度全部复用运行内核，不另起一套执行引擎。

## 域模型

| 实体           | 存储                                | 说明                                                                 |
| -------------- | ----------------------------------- | -------------------------------------------------------------------- |
| 患者档案       | `patients` 表（JSON）               | 姓名、性别、出生年、电话、分组、标签、备注；`archived` 归档标记       |
| 病例工作区     | 复用 `sessions`（含 `patientId`）   | 每位患者一个会话；材料、运行记录、产物、复核历史都在这里             |
| 患者消息       | `patient_messages` 表               | 来源渠道（ingest/manual）、方向 in/out、时间、`external_id` 去重、已处理标记 |
| 随访计划       | `follow_ups` 表                     | 名称、间隔天数、随访要点、是否授权自动总结、下次到期时间、历史        |
| 提醒           | `reminders` 表                      | 随访到期生成，pending → done（医生手动确认）                          |

数据库 schema 由 2 升到 3；升级只建新表，不改既有会话数据，旧库原地在首次启动时迁移，`npm run backup` 兼容两个版本。

## 闭环流程

1. **建档**：患者管理 → 新建患者（姓名、电话、分组、标签）→ 自动创建「姓名 · 病例」工作区。
2. **导入材料**：在患者详情「打开病例工作区」后按原工作台流程导入 TXT/MD/CSV/JSON/PDF 文本；材料不跨患者混用。
3. **自动整理病例**：患者详情一键发起本地模式运行，三个医疗子代理（时间线 / 检验摘录 / 用药核对）并行产出待复核草稿。
4. **评估治疗方案**：模型模式下由模型调用 `draft_treatment_review`，产出固定结构的参考意见草稿（现状摘要、需关注点、信息缺口、建议核对的问题），走既有产物复核流程。没有药物知识库、剂量或相互作用判断。
5. **随访计划**：按间隔天数到期执行——先生成提醒；若计划带外发授权且模型可用，则把未处理消息组合成一次摘要运行（独立上下文、幂等 requestId），完成后消息标记已处理、产物进入工作区。
6. **提醒医生**：患者总览「待办提醒」列出 pending 提醒；医生确认后标记 done。本期只有应用内提醒，没有系统通知。
7. **私域消息归档**：见下节。

## 消息接入契约

`POST /api/ingest/messages`（需要 `X-Ingest-Secret: <MEDICAL_INGEST_SECRET>`；未配置该环境变量时接口整体关闭，fail-closed）。接口只监听本机，供本机桥接工具调用；浏览器 UI 的手动粘贴走 `POST /api/patients/:id/messages`（普通令牌鉴权，channel 记为 manual）。

```json
{
  "messages": [
    {
      "externalId": "wx-msg-001",
      "patientHint": "13800002222 或 患者姓名",
      "channel": "ingest",
      "direction": "in",
      "time": "2026-09-07T09:00:00+08:00",
      "text": "今早血压 150/95"
    }
  ]
}
```

- 单批最多 200 条；单条文本 ≤ 5000 字符；`direction` 必须是 `in`/`out`。
- 匹配：`patientHint` 先按电话（去符号后）精确匹配，再按姓名精确匹配；两者都未命中时消息进入待认领收件箱（`GET /api/inbox`），医生在界面上认领。
- 去重：`external_id` 全局唯一，重复推送返回 duplicates 计数，不产生重复记录。
- 消息只存本机 SQLite，导入本身不触发任何外发；只有医生点「AI 总结」或随访计划带授权时才按 consent 规则外发原文。

本项目不包含任何微信协议实现或客户端注入。第三方微信 CLI 由使用者自行部署，通过上述 HTTP 契约推送消息；该 CLI 自身的合规与账号风险在项目边界之外。macOS 侧的界面自动化桥接见下节。

## macOS 微信桥接（界面自动化）

Mac 上没有可用的官方 API 或成熟的第三方 CLI 时，桥接以**系统级界面自动化**（System Events / JXA，等同于 Windows 侧 UIA 工具的思路）直接驱动本机微信客户端：不注入、不逆向协议、不联网。

- **开启方式**：`.env` 设置 `MEDICAL_WECHAT_BRIDGE=on`（默认关闭），并给运行服务的终端授予 系统设置 → 隐私与安全性 → **辅助功能** 与 **自动化** 权限；未授权时接口返回 503 并提示授权路径。`MEDICAL_WECHAT_PROCESS` 可指定客户端进程名（默认探测 `微信`/`WeChat`）。
- **读取（同步当前聊天窗口）**：医生把微信切到该患者的聊天窗口，在患者详情点「同步微信当前聊天窗口」。桥接抓取当前窗口的可见文本（递归 AX 树，上限 300 条/5000 节点），按患者强制归属后走统一 ingest 管道（去重、审计）。微信不提供消息时间戳，导入时间以同步时刻为准；`external_id` 为 内容哈希，重复同步自动跳过。
- **发送（回复草稿）**：患者详情写好回复后点「通过微信发送」。桥接激活微信 → Cmd+F 搜索（优先用患者电话，唯一性更好）→ 剪贴板粘贴 → 回车选中 → 粘贴正文 → 回车发送；随后把发出内容记录为 direction=out 消息。**每条消息都必须医生逐条点击确认，系统没有任何定时、批量或自动发送路径。**
- **已知限制**：界面自动化依赖微信版本的 UI 结构，快捷键（Cmd+F）或界面改版可能导致失败；搜索取第一个结果，请确保搜索词能唯一定位患者（建议资料里填手机号）；发送过程会临时占用并恢复剪贴板。自动化客户端存在违反微信使用条款导致账号受限的风险，由使用者自行评估。界面结构异常时运行 `npm run wechat:inspect`（需先授权）查看当前 AX 树以校准。

## 随访语义（与调度器一致）

- 同步领取、单机单 owner；错过多个周期合并为一次执行，按原节奏推进下一次到期时间。
- 摘要运行失败时计划暂停并记录原因，恢复后创建**新的**未来执行点，不自动重放不确定的请求。
- 服务重启将 running 标记为 interrupted → paused，不伪装成功。
- 未授权外发（`externalConsent: false`）或未配置模型时，到期只产生提醒，消息保持未处理，由医生手动总结。

## API 一览（均需 X-Medical-Token，除 ingest 用独立密钥）

| 请求                                    | 用途                                       |
| --------------------------------------- | ------------------------------------------ |
| GET/POST `/api/patients`                | 列表（q/group/archived 过滤）/ 建档       |
| GET/PATCH/DELETE `/api/patients/:id`    | 详情 / 更新（expectedRevision 乐观锁）/ 删除（级联清理工作区、消息、随访、提醒） |
| GET/POST `/api/patients/:id/messages`   | 消息列表（unprocessed=1）/ 手动导入        |
| POST `/api/patients/:id/messages/digest`| 手动触发 AI 总结（需 externalConsent）     |
| GET/POST `/api/patients/:id/followups`  | 随访列表 / 新建                            |
| PATCH/DELETE `/api/patients/:id/followups/:fid` | 暂停恢复 / 删除（按 revision）     |
| GET `/api/reminders`、POST `/api/reminders/:id/ack` | 待办提醒 / 确认               |
| GET `/api/inbox`、POST `/api/inbox/:id/assign` | 待认领消息 / 认领                   |
| GET `/api/wechat/status`                | 微信桥接状态（启用/权限/进程探测）          |
| POST `/api/wechat/read`                 | 同步微信当前聊天窗口到指定患者              |
| POST `/api/wechat/send`                 | 发送一条医生确认过的回复草稿（单条、逐条）  |
| POST `/api/ingest/messages`             | CLI 消息接入（X-Ingest-Secret）            |

## 明确不做

- 不自动向患者发送任何消息；微信桥接发送只能由医生逐条点击触发，AI 只产出草稿。
- 不注入或修改微信客户端，不逆向微信协议；自动化只通过系统辅助功能接口驱动官方客户端。
- 治疗评估不构成临床决策支持：没有药物知识库、剂量计算、相互作用判定，产物必须经医生复核。
- 不做多医生/多用户、远程访问、HIS/EMR/FHIR 对接；数据仍只在本机 SQLite。
- 系统级通知（桌面推送）留给桌面版后续版本。
